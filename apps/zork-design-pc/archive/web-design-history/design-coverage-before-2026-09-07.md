## A. 完全没有对应稿：3 个任务

| 优先级 | 缺口 | 现有实现 | 需要补的设计状态 | 需要补的组件 |
| --- | --- | --- | --- | --- |
| P1 | 模型接口协议菜单 | `model-protocol-compact/wide` | 收起、展开、当前选中、键盘移动、不可选；协议与供应商图标的关系 | 带图标的协议选择器 |
| P1 | Agent 模型连接菜单 | `agent-dropdown-compact/wide` | 连接名称与供应商身份、展开/选中、空连接、加载失败、切换连接后重选模型 | 连接与模型联动选择器 |
| P1 | 会话执行历史 | `conversation-history-compact/wide` | 收起/展开、运行/完成/失败、空历史、长记录滚动、定位来源消息 | 历史入口、事件行、执行分组、详情内容 |

补齐验收：每项提供两种窗口的实际设计页面；示例参数与原生一致；交互可操作；再录入原始参考抓取和组件工作台。历史当前只有原生快照，Web 交互也需单独接入。

## B. 已有稿但字段不全：3 个表单任务

| 优先级 | 表单 | HTML 已定义 | 原生新增、需要定稿的部分 |
| --- | --- | --- | --- |
| P1 | 添加/编辑模型 | 模型 ID、上下文与输出容量 | 接口协议、可用推理级别、默认推理级别；容量校验与错误位置；确认/返回动作 |
| P1 | 添加 Agent | 名称、角色、连接、模型 | 头像选择、职责与偏好、Worker 授权范围；整张表单的字段顺序与窄窗口滚动 |
| P1 | 编辑 Agent | 名称、角色、连接、模型 | 头像编辑、模型配置与头像分开保存；需要统一哪些内容可编辑、如何保存和取消 |

不能仅把原生多出的字段贴到 HTML 里：先定字段顺序和保存行为，再统一两侧组件。连接、模型、名称等共同初始数据已经一致。

## 本轮正在补齐的公共控件

- **供应商身份**：连接、模型和协议选择器的触发器与选项行都使用共享供应商图标；修正只在“添加连接”有图标而 Agent 表单遗漏的问题。
- **Switch**：独立公共组件；关闭、开启、禁用关闭、禁用开启、键盘焦点，共 5 个状态。支持点击、Space / Enter。
- **按钮**：统一高度改为 32 px，沿用现有文字、圆角和横向内边距；原生与 HTML 参数同时调整。

## 补齐顺序与交付口径

1. **先完成 P1 表单与选择器**：模型、Agent 共享一套字段、供应商图标和菜单行为，把 A 的前两项与 B 合并推进，避免重复画稿。
2. **补执行历史**：确定信息层级和展开方式，再抽历史组件并接 Web 可交互示例。
3. **补客户端与组网设置**：先核实用户可见行为，再完善账号/设备状态，不把内部实现参数直接放进用户流程。
4. **收录已有设计的公共部分**：通用弹窗、设备、评论、附件，逐组补独立示例。

每项完成须同时具备：设计来源、共享参数、正常/空/禁用/加载/错误等适用状态、键盘操作、两种窗口检查、原生与 Web 的同源组件。深色主题与移动端完整组件覆盖另开范围，本次不计入 PC 缺口数字。
