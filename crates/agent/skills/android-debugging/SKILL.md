# Android 调试协作

接通手机并完成用户实际要求的开发、安装或排障。Agent 负责环境检查、命令执行、结果验证与恢复；用户只承担必要的插拔线、系统开关和授权确认。不要把终端命令、整份设置清单或可自行发现的信息交给用户处理。

每次只说明当前阻塞和最少的下一步。检测到条件满足后自动继续，不再要求用户额外回复“完成”，也不为已经授权的后续步骤重复请求许可。仅在目标仍有歧义、缺少实际执行能力或确实需要用户参与时停下来。

## 先检查，再引导

经 Zork Mesh 调试时，在执行任务的 Station 上运行 `adb devices -l`。Station 会把已启用的手机桥接连接到本机 ADB server，loopback serial 就是普通 ADB 目标，不需要专用发现工具。用序列号和型号确认目标，再用 `adb -s <serial> get-state` 核对可用性。

每台已接入的 Station 都能独立连接，loopback serial 只属于该电脑，重连后可能变化。需要另一台 Station 的连接时，通过 shell.run 的 target 在那里执行 ADB；不把它的 localhost 地址当成本机目标。没有连接时先检查 Mesh 和手机 Zork 的安卓调试设置，保留已有成员关系、配对和系统授权。

在对应电脑上使用 `shell.run` 等已有执行工具。先寻找配置的 SDK、常规 SDK 目录及 PATH 中的 ADB；确实缺失时，按该节点环境规则安装官方 Android SDK Platform-Tools 并验证可执行，不要求用户手工安装整个 Android Studio 或自己打开终端。

只有当前系统状态需要时，才引导用户开启开发者选项或 USB 调试；先给当前设置入口，回来后重新观察。Mesh 成员身份和 Android 的 ADB 授权分别处理，不能互相代替。

## 由 Agent 代办 USB 激活

需要跨网激活时执行这条流程；它不改变手机允许多台 Station 连接的规则。

1. 确定手机实际插入哪台可执行命令的电脑。在那里运行 `adb devices -l`，识别当前物理 USB 设备，排除模拟器、Mesh loopback 和系统无线 ADB 条目。结合已知序列号、型号与用户上下文确认目标；只有一个匹配目标时直接继续，不能凭型号在多台相似手机间猜测。
2. 尚未插线时，只请用户把手机用数据线接到这台电脑。已经检测到则跳过。使用有期限的 ADB 等待或检查跟随状态变化；没有变化时保持安静，期限结束只说明仍缺少的动作。等待归属当前任务，完成或取消时回收，不默认启动常驻 USB 监听。
3. 显示 `unauthorized` 时，只请用户解锁手机并允许这台电脑的系统调试弹窗。允许后重新读取设备信息并继续；不清除既有密钥、伪造授权或重复要求已完成的系统设置。
4. 重新确认选中的 USB transport 仍在线且已授权，然后由 Agent 执行 `adb -s <USB_SERIAL> tcpip <PORT>`。`USB_SERIAL` 来自本次发现，`PORT` 与该手机 Zork 安卓调试页面显示的端口一致；替换参数并正确引用后执行，不把占位命令交给用户。如果之前执行结果不明，先检查手机与 Mesh 的当前状态，避免盲目重复重启 adbd。
5. 命令成功仅表示已请求切换。在执行任务的 Station 重新运行 `adb devices -l`，等待目标连接出现并完成系统授权，再用最新 serial 运行 `adb -s <serial> get-state` 验证连接。只有端到端可用后才告诉用户可以拔线；验证跨网时再按需请用户切到蜂窝网络并复查，不把同网连接当作蜂窝验证。

手机重启后可能需要再次激活，但先检测，不能要求用户每次重做。系统无线调试开关本身不证明蜂窝 Mesh 已就绪。

## 处理当前故障

- 电脑看不到 USB：先检查实际 USB 枚举、ADB 与该平台驱动，只有证据指向线缆、插口或系统确认时才请用户处理相应项。不要一开始就让用户尝试全部排障动作。
- Station 离线、缺少 ADB、版本不支持或授权被拒：按当前提示在拥有问题的电脑诊断并处理；一次只修当前原因。用户只需完成 Agent 无法代办的系统确认。一台 Station 的故障不影响另一台已连接 Station，不重置健康连接来修复故障连接。
- 控制连接中断或 serial 变化：复查 Mesh 和手机状态，使用新返回的 serial，沿用已有配对。不要另起通用隧道或重启共享 ADB server；确需隔离诊断时只创建和回收本任务的进程。

用户明确选择普通 USB 或系统无线 ADB 时，遵循其连接方式。无线 ADB 先用 mDNS 发现当前服务并复用已有配对；自动发现失败后才索取缺失的地址。只有当前可达的手机确实未配对或拒绝既有身份时，才引导打开配对页面并提供本次所需配对信息；不要记录配对码，也不因设备列表为空要求重新配对。

## 完成任务与收尾

连接是前置条件，继续完成用户要求的安装或调试。安装时复用用户指定的 APK，需要构建才执行项目脚本；固定产物并记录摘要，核对应用 ID 与签名兼容性后用 `adb -s <serial> install -r <apk>` 保留数据安装。设备命令始终指定本次确认的 serial。验证已装版本、产物摘要及目标应用启动；日志限定时间、包名或 PID。验证范围按任务与节点环境规则选择，不因安装请求额外操作用户的整部手机。

Zork 自身开发时，将目标 APK 的应用 ID 与 `bridge_application_id` 比较。承载桥接的应用必须保持可用，优先用独立应用 ID 的开发包；不能假定桥接宿主就是稳定版。若用户要求更新桥接宿主，先准备能恢复的 USB／系统无线 ADB 等独立通路；覆盖安装中断 Mesh 后重新连接并核验结果。连接中断时先检查安装是否已经完成，再决定是否重试。

清理本任务的等待进程、临时转发和占用锁，保留用户的数据、身份、配对与健康连接。只汇报实际完成的连接方式、安装／调试结果和仍需用户参与的动作；构建成功、激活命令成功和安装成功分别核验。

用户要求结束调试时，区分关闭 Zork Mesh 桥接和关闭系统 adbd。关闭手机 Zork 中的调试只回收桥接；要同时结束系统 TCP 调试，可在当前连接上执行 `adb -s <serial> usb` 并预期断线，或按需引导关闭 USB 调试。不要在仍需连接时提前关闭它。

ADB 平台行为与安装入口按需查阅 [Android 官方文档](https://developer.android.com/tools/adb)；以当前 ADB 连接和手机调试页面为准。
