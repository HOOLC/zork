# 模型连接与账号选择

Profile、额度和账号池属于执行节点；客户端通过共享 core 管理其授权投影与操作。本文规定模型选择和账号使用规则，客户端偏好见 [界面规范](interface.md#client-preferences)。

<a id="models"></a>
## 模型连接与额度

Profile 凭据保存在托管节点，Agent 引用身份与模型选择。重命名保留 ID、引用、凭据和配置。连接与模型编辑使用预期版本，仅修改指定字段；模型目录刷新保留手工配置和启停状态，不删除本次供应商未返回的模型，不补造缺失上下文/输出上限。

客户端 core 内置常见模型的参考参数（上下文、最长输出、思考方式、输入能力），按模型 ID 识别后只预填编辑器中尚未设置的字段，并为每一项提供“参照”取值；保存前由用户确认，刷新目录时不自动写入。参考值以供应商文档为准，未核实前标记为未验证。思考方式按模型的实际做法表达：不支持、固定开启、开关、原生档位名（如 minimal…xhigh）或 token 预算（可含动态），仍以 thinking 取值列表与默认值保存，界面不使用统一的固定档位。

停用模型阻止新选择及后续调用，不中断已发出的请求。重复保存/启停不产生无效写入或同步通知。token 输入和展示可使用十进制 K/M，但保留精确数量。

额度、账号验证和配置存在是不同状态。只有真实带单位的供应商数值可显示为余额；未知不当作零或无限，零额度仍显示。保留采样时间，使用相对时间说明新鲜度；原始供应商错误不进入额度文案。失败保留旧数据并显示失败，旧请求不能覆盖新额度。

core 协调可见性、刷新、新鲜度和同 Profile 请求合并，UI 不设置业务轮询。各 Profile 不共用一把网络请求锁，额度失败不丢弃已成功刷新的 OAuth 凭据。供应商接口、采样周期和容量参数由实现及适配测试维护。

<a id="account-pool"></a>
## 自动账号池

自动选择是持久意图，实际使用账号是每次调用事实；固定账号失败不静默换号。池只包含执行节点本地 Profile，不汇入其他节点的凭据或占用。

候选必须满足凭据、已启用模型、thinking、模型上限和输入类型。排除明确鉴权/额度失败或相关额度耗尽的账号；未知额度仅作兜底，不比较不同单位余额。订阅优先、按量付费兜底，评分考虑剩余额度、重置时间与进行中调用；具体算法在账号池实现中维护。

附加 credits 与基础订阅窗口分开，前者零余额不证明订阅额度耗尽。

选择与预占原子完成，固定账号也计入占用，成功/失败/取消均释放。后续调用可以复用上次实际账号，但必须仍符合条件；实际账号随持久模型结果恢复，不靠内存分配表推断。调用预算采用兼容配置的保守上限，额度变化不能扩大上下文预算。

自动故障切换仅允许在本次调用尚无任何输出时、有界地尝试其他候选；已有部分输出交回运行时恢复。所有候选不可用时明确失败，不退回已耗尽或冷却账号。过重置时间不凭空补满额度。换号后不复用不匹配的 provider 连接或加密续链。


验证并发配置、凭据恢复、额度缺失/失败、账号预占和部分输出后的恢复；具体入口见 [验证规则](../../.agents/skills/zork-validation/SKILL.md)。
