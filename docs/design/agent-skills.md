# Skill 目录来源

<a id="content-boundary"></a>

## 内容职责

Zork Agent 的 Skill 与 `tool.help` 各自维护不同内容：

- `tool.help` 是工具手册：用途、调用格式、参数与返回值、标识符语义、约束、错误语义及处理方式，以及分页、上传等接口要求的操作步骤和调用示例。具体合同由工具实现与帮助维护，不在 Skill 中另存一份。
- Skill 是最佳实践：何时采用某种做法、怎样判断与取舍、业务场景下如何组织任务、如何检查结果质量，以及需要避免的领域陷阱。可以指向相关工具的 `tool.help`，但不复制参数表、接口清单或操作手册。

区分依据是内容职责，不是篇幅或步骤数量。接口规定的多步调用仍属于手册；Skill 中的任务安排应解释业务判断及其理由。示例用于说明判断，不把 API 手册改放进示例或 references。若缺少完成任务所需的调用说明，补齐对应的 `tool.help`，不以 Skill 代替。

## 文件与来源

Skill 是真实目录中的 `SKILL.md` 和相对资源。Agent 使用通用文件工具读取、修改、复制和物化；来源清单由运行时在模型请求前提供，不增加专用的文件操作或清单查询工具。

Skill 使用独立的 Synch space，与[共享文件入口](shared-files.md#spaces)和内部控制 space 分开。用户的专用 Skill UI 与 Agent 消费同一文件权威。默认目录由运行时提供，不能从 UI 名称推导本机物理路径。

公用来源可跨节点自动发现；与本机路径、硬件或工具链相关的来源限于该节点。Mesh 成员互信，显式读取文件和是否自动加入 Skill 清单是不同问题。同名候选保留各自来源、完整路径和内容哈希，不按名称覆盖。

## 配置与发现

节点配置和 Agent 配置决定附加来源。来源变更通过既有配置入口完成，不另设 Skill 来源管理工具；接口、字段及限制以配置源码和生成帮助为准。远端 Worker 使用执行节点自己的配置，不继承 Leader 的本机路径。

每次普通模型请求前刷新配置与清单；仅变化时追加持久记录，压缩或交接后重新提供当前清单，不改写历史前缀，也不在空闲时轮询。

发现按通用目录接口分页。遇到 manifest 或历史归档边界后停止深入资源，隐藏目录与符号链接子目录不自动遍历；显式来源根可以是目录符号链接。规范路径相同的来源去重，同名但不同路径的候选保留。单项损坏、缺失或超限提供局部诊断及可续读范围，不阻止健康来源或节点启动。

远端选择固定 origin 与树 snapshot。正文 root 只定位文件内容；相对资源去掉 root、继承 snapshot。快照不可用时明确失败，不把旧正文与新资源混读。脚本需要本机路径时使用通用文件物化，保留整棵子树的版本和执行位；物化不等于安装或绑定来源。读取正文不自动执行脚本。

## 修改与软件分发

普通 Skill 通过文件操作管理；修改前读取现有内容并保留并发工作。正文及资源共同构成 Skill，不能把附属文件当作可随意删除的缓存。格式与扫描规则由解析器和测试维护，不在本文复制限制清单。

软件分发项在各自 `.zork/` 保存状态和不可变完整版本，准备并校验后才原子切换活动选择。当前只读视图可恢复，不重复发现、不绕过停用；历史版本及已返回路径继续可读。该约定不构成本机文件安全沙箱。

用户同名目录和改动保留原位，分发项为冲突分配稳定的新目录；迁移继承原选择与历史，提交前旧选择继续有效。定制时复制完整目录到普通来源再修改，更新器不自动合并、搬移或备份用户副本。

停用按稳定的分发目录身份保存，升级、重启和回滚不重置。回滚只选完整版本，并检查当前视图的外部修改；同内容重启保留选择，新分发内容到达后才恢复正常升级。损坏管理记录隔离并报告，不当作空状态重建。分发版本由完整文件内容确定，内容未变时不重复安装。

## 验证

按 [运行时 Skill](../../.agents/skills/zork-agent-skills/SKILL.md) 与[验证规则](../../.agents/skills/zork-validation/SKILL.md) 检查来源、同名候选、普通文件操作、版本选择、资源完整性及历史前缀。进程测试先构建当前 Station，再运行 `scripts/test-skills.py`；假模型只能证明调用链，不能证明真实模型遵循指引。
