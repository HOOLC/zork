# Chat 与协作

Chat 是授权 Mesh 内的公开协作频道；Session 是内部模型和工具执行上下文。结果、验收意见与修改要求都是消息，不使 Chat 进入完成、取消、待验收或重开状态。

## 身份与消息

- Chat、消息、Agent 和执行上下文各有稳定身份。创建者、实际作者、订阅者和执行者分别表达；读取或发言不要求先订阅，订阅但未发言不增加作者。
- 可信身份由执行上下文与认证节点绑定，消息正文、工具参数和 instructions 不授予权限。跨节点引用保留 origin；显示名、本地路径和模型自报身份不能决定远端对象。
- Station 将消息、作者事实和附件固定引用作为完整源记录提交，持久化后才发布；任一引用或校验失败不能留下部分可见的源消息。业务工具的效果与回执遵循原业务的提交和恢复边界。
- 客户端发送前由 core 将消息写入本地 SQLite，状态为发送中，UI 直接显示这条记录。源消息回推后更新同一条记录为已发送并补齐源元数据；发送失败更新为失败。其他来源的消息收到后保存为已发送。普通消息的本地正文与发送状态属于同一记录，不另存一份待发送消息再迁入已收消息。
- 普通消息以源端持久化后的原消息回推确认发送，不另建发送确认回执，不自动重试。用户失败后手动重发算新的发送，分配新的消息身份；Station 每次接受发送就追加，不查重，消费者也不合并不同发送。两次发送都到达时保留两条消息。订阅重连与补拉按读取恢复处理，补拉到回推对应的源消息也更新本地发送状态；已发送状态不被迟到的失败结果回退。
- 用户正文原样呈现，包括 Markdown 标点、换行、复制和引用内容；Agent 消息可以渲染 Markdown。内部推理和 assistant transcript 不自动发布。
- 搜索和历史读取同时受记录数、字节数约束；游标推进到实际返回的最后记录，不跳过未返回内容。被折叠的源记录仍计入读取进度。文件遵循 [共享文件与附件](shared-files.md#attachments)。

工具参数由运行时 `tool.help` 生成。发现、创建、发言和直接请求使用当前 `chat.*` / `agent.*`；对象 ID、分页游标与输入水位不互换。

## 本机脚本卡片

本机脚本随普通 Chat 消息发布，承载显式的平台、接口版本和 JavaScript 源码。用户在兼容的 Android 客户端点击后执行本机能力；PC 与未知版本只读展示。消息到达、缓存重建、分页、重连与视图重建都不启动脚本，普通正文也不是可执行输入。

发卡按消息发布完成，不登记待响应请求，不等待执行，不回传日志或结果，也不接续 Agent 调用。用户自行在后续消息中说明操作情况。系统权限与 Activity 回调只返回本机脚本；执行状态不修改消息源，也不成为跨端共享的卡片结果。

core 从实际缓存消息读取源码，管理校验、执行范围、取消和资源上限；平台适配只处理 core 请求的系统能力。平台请求执行前必须由 core 认领，重复观察或迟到回调不能重复执行、推进下一次运行。关闭观察不重放已认领动作；客户端重启不恢复脚本副作用。取消阻止后续步骤，已开始的原生操作遵循系统自身的取消能力。平台入口与权限条件见 [Android 本机操作](../guides/android-local-operations.md)。

## 消息源与恢复

每个 Chat 在 Station 数据根的 `chats/<chat-id>/` 下保存消息源：`.zork/source.json` 保存来源身份与 epoch，`messages/` 保存按首个源位置命名的 JSONL 段。活动段只追加；封存段压缩为含独立小帧的 `.jsonl.zst`，逐页读取不必解压整个归档。完整源记录包含作者、正文、固定附件引用、回复、提及及业务卡片快照；压缩不改变记录或源位置。

Station 使用单一写者。业务事务可以暂存待发布消息；只有完整源记录刷盘成功后才清除暂存正文并回推。重启恢复已提交事务的物理日志前缀，不重发网络请求。活动尾部未完成的行不作为已发布记录；完整行损坏应报错，不能静默截断已发布历史。

消息位置索引与业务查询投影可以从源日志重建，索引不另存正文。重建不重新派工、投递已接受输入或恢复已删除的业务绑定；会话、权限、业务回执及文件本身仍需保存，不能把消息索引可重建理解为整个 Station 数据库可删除。压缩先写临时文件、校验并持久替换，再删除旧表示；读取和替换保持一致。

游标绑定 Chat 与 epoch，源位置允许跨频道分配造成的跳号。正常重启、压缩和索引重建保留 epoch；从旧备份恢复为新的消息来源时，停机恢复完整业务数据、消息源与附件，并为受影响 Chat 的来源元数据分配新的 epoch，再启动客户端读取。旧游标必须失效，不能将新来源接在旧缓存后。备份必须同时保留来源元数据与消息段；只备份 SQLite 不能恢复消息正文。旧版本只识别 SQLite 正文，回退必须恢复迁移前的相容备份，不能仅替换可执行文件。

## 订阅与接收

每个 Agent 独立配置某个 Chat 的订阅、筛选与投递方式；更新只覆盖给出的字段，用预期版本拒绝旧编辑。首次订阅从后续消息开始，重放历史必须显式给出该频道的起点。

提及和回复引用是结构化消息事实，不能从正文中的名字猜身份，也不能越过退订。发言者自己的输出不经频道订阅回灌自身。即时输入可唤醒空闲 Agent；下一轮输入先持久排队，在正常运行或模型边界消费。

偏好变更使尚未交付的旧代通知失效。接收页和向 Agent 投递前都检查代次；已经持久接受的输入不因退订撤回。不同 Agent 的设置、失败与退避彼此隔离。

三个确认边界必须区分：

1. 源端已将通知放入传输队列。
2. 接收节点已将收件数据与恢复游标一起提交。
3. Agent 已持久接受输入来源水位，Station 随后记录投递完成。

断线从第二个边界恢复，Agent 按第三个边界继续接收后续源位置；它们都不是 UI applied version。已提交的同一源位置不重新入队，用户手动重发产生的新消息正常接收。同一 Agent/来源不越过失败的较早位置，慢 Agent 不阻塞整个节点。源消息回推确认消息已保存，Agent 是否接受输入、运行和完成分别表达。

## 创建归属与执行

日常导航按设备 → 长期伙伴 → 它创建的 Chat 组织，完整 Agent 配置目录独立存在。创建者在可信创建事务中保存，不随作者或订阅变化；旧记录只在有可靠事实时补归属，否则保留未知。执行设备的镜像不重复显示为另一件工作。

未读优先提升所属分支，其他顺序来自真实消息时间；执行心跳不改变最后消息时间。core 提供归属、顺序、未读和可打开状态，UI 仅保留选中、展开与滚动。成员关系不能用来猜创建者，旧任务终态不决定新 Chat 的显示或发送能力。

长期伙伴使用持续上下文。创建 Agent 定义、打开便捷 home 或订阅 Chat 不启动一次任务执行；明确派工才为新工作建立独立 Worker Session 与 Chat。同一次调用恢复沿用原分配，后续返工保留该工作的绑定；不能将输入送入同一 Worker 的其他任务。

工作权威留在调用节点，执行事实由实际执行节点保存。客户端在哪台机器上发送不改变归属；断线不自动切换执行者。分配建立接收关系时从初始工作消息之后回放，保留早到结果，避免初始请求重复入队。实际作者、主页伙伴与明确 assigned 执行者可共同用于成员呈现，但 assigned 不增加公开作者计数。

直接 Agent 请求只证明输入已排队；它不会代对方订阅、发言或接受委派。停止须绑定观测到的具体 run，旧请求不能误停下一轮；已请求中断与清理完成分开。停止不关闭 Chat。

## 配置与执行上下文

模型、说明和 Skill 属于 Agent 定义；频道偏好属于 Agent 与 Chat 的关系。配置在同一权威版本上更新，保留未修改字段；在途模型请求保留已冻结配置，后续边界采用新值，不重置既有上下文。

Session 自通知只回到调用者自己的收件箱，不产生 Chat 消息、作者或系统通知。用户参与沿 [原业务工具](user-participation.md) 保持 pending 并接续；公开 request_id 不改变执行与权限所有权。

Chat Agent 按 [turn 结束确认](agent-runtime.md#turn) 处理无工具的 assistant 收尾：内部正文留在 Session history，所需回复由模型主动发布，确认无需再发时用 `end`。发帖成功与模型处理成功独立；提醒不自动重发已提交或结果不明的消息。provider 或结束确认失败通过执行状态与历史保留具体原因。

主动投递未填写 Chat 时，目的地来自本次执行的真实绑定：长期伙伴使用 home，Worker 使用该次 assignment 的 Chat，远端执行回到工作所属节点。不能借用另一份工作或 Worker home；显式指定其它节点时必须给出 Chat。

后台 job 的终态与待投递 Session 事件原子提交，自通知也先持久排队。投递按 Session 保序，已接收的来源水位防止确认丢失后重复唤醒；收到 Agent 的持久确认才移除待投递记录。Station 重启恢复未投递事件；配置为不可重启的在途 job 报告效果未知，不重放命令。后台结果唤醒后仍遵守同一结束确认与主动发帖规则。

<a id="compatibility"></a>

## 兼容与保留

旧任务、决策、运行、文件引用和回执保留历史身份。旧 accept/reopen/cancel 接口仍按原 revision、owner 与运行状态校验；不将旧决策伪造成新消息，不用旧 review/completed/cancelled 锁住 Chat 输入。兼容工具不作为新模型的默认工作流。

文件的新内容版本使相关旧验收引用失效；运行结束不等于用户接受，用户沉默也不构成验收。未知外部效果不自动重做。

工作目录自动归档仍是待实施目标：只处理已终结、无活跃运行/子进程且产物已保存的 Worker 托管目录。保留 Chat/Session 历史、原路径和可恢复 manifest；不移动长期伙伴目录或用户外部项目。保留期需配置，归档幂等，继续工作前恢复同一目录。此目标不授权当前清理用户目录。
