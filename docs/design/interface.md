# 共享界面设计

桌面沿用已确认的 Zork 设计，原始资源的来源和许可保存在 [共享资产](../../crates/zork-ui/assets/interface/README.md)。Android 的触屏几何与系统输入见 [移动端设计](../../apps/android/design.md)。产品归属、权限和操作结果来自 [core](client-core.md)，不在视觉规范再定义 API。

## 视觉与组件

暖纸打底、炭墨写字、柿橙点睛，控件为胶囊、容器为大圆角。颜色、文字角色、密度、间距与轮廓由共享组件持有；页面选语义与尺寸变体，不逐页拼普通 hover、边框和字体参数。新变体需真实重复用途，并同时提供示例。

颜色各有唯一含义：主操作用炭墨；柿橙只表示“正在工作”和发送，不表示失败、未读或离线；键盘焦点环是唯一例外，它标明键盘位置而不表达状态，需要在任何底色上醒目；设备色只标明设备身份，按设备稳定分配，不表达状态；Agent 色（`AGENT_TINTS`，圆形色盘）只标明哪个 Agent 在说话，色相避开设备色与状态色，不表达状态；状态色只表达状态。折角来自品牌标志，是唯一的装饰母题，只用于设备标识的右上角和用户消息的收角。

层次只靠间距、分组和底色，不使用分割线：列表行之间、区块之间、步骤之间都不画线。页面本身是一个面，分节只用标题和间距，不在卡片里再套卡片；列表行静止时无底色，悬停和选中才出现。

第一眼只呈现完成当前任务必需的信息：能自动得出的值直接填好并收起，需要时再展开编辑；非常规选项、技术细节（请求字段、协议参数、调试信息）用弱化文字、信息图标或悬停呈现，不与主要内容争夺注意力。

面板按内容定尺寸：留白用来分组，不用来撑大面板。弹窗按内容分三档宽度（确认约 400、表单约 480、详情约 560），内边距 20–24、标题 16–17 px，高度随内容，不设填充用的最小高度；较小的弹窗用容器圆角 24。浮层宽度随内容并有上下限，内边距 6–8；卡片内边距 14–16，不设最小高度；空状态是一行说明加操作，不做居中大块。设置与详情页的内容列居中，宽度为 min(760, 页面宽度 − 64)，页头的返回、标题和操作与内容列对齐，返回按钮可以放在列左缘外侧；分节间距 24–32；单行列表行 36–40。

所有小组件默认由内容与内边距决定宽度，由实际内容布局决定高度。除非设计合同或调用场景明确指定尺寸，否则不设置固定宽度或高度；内容、文字和语言变化后重新测量。容器填充、视口上限和动效布局不应把固定尺寸传回组件作为默认值。

圆角按角色取值，数值由 `zork-ui` 的 `RADIUS` 持有：按钮、字段、导航行和菜单项在 32 px 控件高度下是胶囊；可增高的内嵌块（代码块、附件、多行字段）16；卡片、菜单、浮层与提示条 24；弹窗等大表面 32；消息气泡 24，折角一侧 8；行内代码与骨架 6。嵌套时内圆角等于外圆角减内边距，胶囊与容器保持同心；大圆角容器的内边距同步加大，内容不贴近弧线。所有圆角都是连续曲率的平滑圆角，达到短边一半时回到正圆，胶囊保持圆头。普通图标操作 32 px、紧凑 28 px，Composer 为 24 px 操作和 14 px 图标。带图标的按钮在图标一侧少 4 px 内边距（紧凑 3 px），抵消图标自身留白。平台触控区不直接套桌面尺寸。圆角、描边和内容裁切由平台原生组件处理，约束见 [圆角规则](../../.agents/skills/zork-rounded-corners/SKILL.md)。

正文、说明和辅助信息有清晰角色及可读对比：辅助文字对比度不低于 5:1，最小字号 12 px（仅快捷键徽标 11 px），不能用过浅文字制造层级。业务状态不只靠颜色：设备在线为实心点、中继为半实心、离线为空心、失败为叉，非正常状态同时显示短文字。PC 客户端与 `zork-design-pc` 共用 Rust 组件，Android 共享语义并保留平台交互；系统授权页遵循其来源。

浅色与深色两套主题使用同一组语义 token，默认跟随系统。选择保存在 core 客户端偏好的 `theme`（跟随系统／浅色／深色），各客户端只应用于本机；桌面另可用环境变量 `ZORK_THEME` 覆盖，便于检视。深色主题逐项核对状态色和对比度，不由浅色值直接反相。

## 交互状态

- hover/pressed 是瞬态，selected/invalid/busy 有独立语义。选中与错误在 hover/focus 下仍可辨：选中行悬停时加深而不被覆盖。keyboard focus 使用轮廓外 2 px 的柿橙焦点环，与任何状态叠加都可辨。
- 普通操作使用中性暖灰反馈，主操作使用炭墨，发送保留柿橙；危险操作使用明确危险配方。深色主题中各状态色单独核对，按下不跳到纯黑或纯白。pressed 不降低文字/图标整体可读性，也不改变字重、尺寸或内容位置。
- 字段 hover/focus 加强边框，底色稳定；invalid + focus 保留错误及邻近说明。文本链接用文字强调，不突然出现整行按钮底板。
- disabled 阻止反馈与激活；busy 保持几何并按操作语义处理重复输入。按钮禁用不代替 core 的业务校验。
- 热区与反馈范围一致，子元素不抢占根控件 hover。嵌套按钮不触发整行操作，仅局部可点的卡片不整卡亮起。
- 控件轮廓与选中态保持静态；减少动态效果直接到目标。触屏不能依赖 hover 才发现关键动作。
- 模态、菜单和组件示例共用焦点域，支持正反 Tab、Esc、系统 Back 与焦点恢复；IME 组合输入不被焦点快捷键误提交。

选择菜单沿用字段的文字、边框和焦点语义。下拉列表与模型选择面板使用独立的暖白静态浮层、24 px（手机 24 dp）容器圆角、细描边、柔和阴影和淡入，内边距 8 px 使胶囊选项与浮层同心；新建 Chat 的模型选择面板使用同一容器圆角。填充、描边与阴影共用轮廓，来源不形变或转移材质。浮层按可用空间放在触发器上方或下方，列表过长时在浮层内滚动，不覆盖触发器或撑开表单。单选提交后关闭，多选保持展开直到用户主动关闭；空列表与禁用状态不可展开。触发器说明当前值和展开状态，选项保留选中语义。桌面客户端与 `zork-design-pc` 共用 GPUI 控件，Android 独立实现 Compose 控件和触摸尺寸；两端共享设计元素与 Rust core 的数值、业务合同，不共享 UI 组件。

## 导航与页面

Chat 层级来自 [导航合同](chat.md#navigation)。桌面导航为 32 px 行，使用普通 hover 和静态选中底色；键盘焦点独立可辨。分组留白、内容缩进不改变热区。Chat 的头像是其中 Agent 头像的叠放：按首次出现顺序重叠排列，最多 3 个，其余合成「+N」圆盘，只有一个 Agent 时就是它自己的头像，没有 Agent 时用普通 Chat 标识；对话头部在标题前使用同一头像。每个 Chat 行固定为两行、行高一致（52 px）：第一行只有标题，占满宽度，过长省略；第二行是弱化的元信息，从行的内容左缘开始，先是小号叠放头像（约 16 px 圆盘，重叠 5 px），不在本机 Station 的 Chat 再写所在设备的显示名称加「 · 」，最后写时间（如「A · 刚刚」，悬停设备名提示「在设备 A 上」），本机的 Chat 只有头像和时间（「刚刚」），不加彩色设备标识。时间文案来自 core `message_time`，文案变化时重绘。侧栏底部的设备坞显示各设备及其连接状态。

侧栏按像素拖动并持久保存，桌面范围 200–420 px；Chat 与设置共用宽度。Agent 消息头显示 Agent 身份（头像 + 名称），模型移到名称的悬停详情，规则见[多 Agent 消息](#multi-agent-messages)。Composer 随内容增高，无手动拖高柄。页面标题、主操作、分区、字段说明与反馈位置复用组合组件。

桌面 Chat 正文完整显示，不按高度截断，不提供消息折叠设置或独立全文弹窗。跟随新消息时定位到该消息开头；用户浏览历史时保留阅读位置并提示有新消息。

新建 Chat 在输入区上方选择执行设备：不超过四台时显示设备标签，更多时改为下拉选择；只有一个目标时不显示。模型选择的主选项是模型与思考强度：面板每个模型只列一次（不论几个连接提供），选中模型的思考强度在下方；连接是可选的次要项，默认“自动”，展开后只列出提供该模型的连接（带供应商标识），自动项以弱化文字说明它会从哪些连接中选。固定连接后换到它不提供的模型，连接回到自动。触发器显示“模型 · 思考”，仅在固定连接时追加连接名，静止时无底色，宽度随内容变化，高 28 px；发送按钮高 24 px。

模型设置是独立入口，按供应商展示各设备的连接卡片，分组标题写“N 个账号”（合并后的账号数）。卡片分两行（与 Chat 列表行同一形式）：第一行是供应商标识和账号标题，标题占满整行、放不下才省略（API Key 的“···末4位”不省略）；第二行是弱化的元信息：标题中尚未写出的接入方式、设备来源、额度、模型数，需要处理时再加验证状态。卡片以账号信息为标题：登录账号显示邮箱或登录名，API Key 显示“接入方式 · ···末4位”，未知时显示接入方式；用户设置过的 Profile 名称弱化显示在账号信息之后，自动生成的名称不显示；名称在新建和重命名时都可留空（规则见 [模型连接](model-connections.md#account-label)）。设备来源、订阅、额度、验证状态和模型数量都显示在卡片中，具体模型进入 Profile 后管理。设备不作为浏览前置选择；同一供应商账号保存在多台设备上时只显示一张卡片，设备来源列为“A、B”，打开后列出各设备的连接分别管理（规则见 [模型连接](model-connections.md#same-account)）；账号不同的同名 Profile 仍是各自的卡片。编辑写回所选来源；新增连接时才选择保存配置的设备。

表单失败或外部更新保留用户输入，列表更新保留阅读锚点与选择。显示实际对象身份和操作阶段，不从点击、网络断开或动画结束推断成功。

设备名称显示 core 提供的 Mesh 显示名称（见[设备命名](devices.md#display-names)），桌面悬停提示登记时的机器名称，名称可能被截断时一并重复显示名称；手机在设备详情中列出机器名称，长按设备标签查看。显示名称在设备设置中原地修改：Enter 保存，Esc 取消，空、过长与重名在字段下方说明。设备名称的展示统一携带 core 提供的连接状态，并复用设备名称与状态组件；文本型菜单和元信息沿用同一状态文案。区分客户端 Mesh 准备状态与目标设备可达性，本机 Station 已在线不能被显示成 Mesh 已就绪。状态只回答“本客户端能否到达该设备”：尚未建立或已停止的连接显示“未连接”，只有连接尝试进行中才显示“连接中”，事件连接一旦建立即按路径显示直连、中继或已连接。Mesh 成员列表中设备之间的连通是另一件事，用文字写明（如“与 mini1 已互通”），不复用状态点；成员是本客户端的设备时，状态点仍显示同一个客户端状态。Mesh 设备列表也列出本机：所列 Station 就是本机时，它排在第一行；查看其他设备的 Mesh 时，本机所在的成员行同样标出。哪台是本机由 core 判定（本客户端自己运行的 Station，以及本客户端自己的 Mesh 身份），两端共用同一规则。本机在名称和状态点之后以弱化文字「本机」标注（状态点在每行位置一致），与其他元信息同样式，不用彩色徽标，并写入无障碍标签；显示名称、颜色标识与机器名称提示与其他行一致，本机行不提供「移除」。手机的 Mesh 列表以本机开头，该行没有点击操作，长按查看机器名称。状态更新随连接生命周期传播，不依赖当前打开的页面，也不把状态文字写回设备名称。

## 多 Agent 消息

以已确认的交互原型为准；值与规则由 core `message_presentation` 提供（分组、时间、色盘、引用内容、省略规则中“之间只有自己的消息”的部分），两端只做布局、悬停和“一屏之内”的测量。

- **身份**：每组 Agent 消息的首行是 Agent 头像加名称。头像是 Agent 的身份色盘，盘内是写这条消息的模型的厂商标识（`model_catalog::maker`，不认识的模型用通用标识），一眼看出能力；不知道模型时（旧消息、远端 Agent）盘内显示首字母（拉丁字母大写，中文取首字）。不使用 `author_avatar` 图片。色盘来自 5 个 `AGENT_TINTS` 槽位，只由 Agent id 的哈希决定（`agent_tint::slot`），不按 Chat 内出现顺序避让：同一 Agent 在对话、Chat 列表与对话头部的叠放头像、回复行和输入框草稿里颜色一致，加载更早历史也不变。同一 Chat 里两个 Agent 可能同色，由厂商标识和名称区分。只有这个 Chat 的 Agent 分布在多台设备上、且不是手机宽度时，才在名称后弱化显示设备名。名称悬停（手机长按）显示「名称 · 设备（机器名） · 模型」。
- **分组**：同一作者、相邻间隔不超过 5 分钟的连续消息成组，身份行只在组首出现；组内间距约 6 px，组间约 20 px，不画分隔线。
- **时间**：每组只显示一个相对时间，Agent 组在身份行末尾，用户组在最后一个气泡下方；组内其他消息悬停时在行末显示自己的时间。完整时间在悬停（手机长按）时显示。文案规则见 core `message_time`：刚刚、N 分钟前、N 小时前、昨天 HH:MM、周X HH:MM、M月D日 HH:MM、YYYY年M月D日 HH:MM，远未来显示日期；按 `next_change` 只在文案变化时重绘。
- **回复行**：Agent 回复是一行弱化文字：↩、「回复」、目标作者（小色盘 + 名称）、引用内容，单行省略，全文在提示里。组首时放在身份行名称之后、时间之前；组内其他消息单独一行放在正文上方。引用内容：原文不超过 10 个字符时原样放在「」里；否则用 Agent 自己写的摘录（「」）或大意（前加「大意」小标签）；旧消息没有引用时显示原文开头。
- **省略**：回复的目标与回复之间只有该作者自己的消息，且原文起点在回复上方一屏之内时不显示回复行。距离按排好的列表计算（虚拟列表用估算高度），不看滚动位置，窗口尺寸变化后重算，滚动时不闪烁。
- **跳转**：点击回复行滚到原消息，上方留约 24 px；摘录能在原文中找到时只给那段加暖色底（不用柿橙和状态色），约 1.6 秒后淡出，否则整条消息加暖色底。原消息已删除时写「回复 X · 原消息已删除」，不可点击；尚未加载时写「回复 更早的消息 · 尚未加载 · 点击加载」，第一次点击只加载更早历史并保持阅读位置（与底部的距离不变），提示「已加载，再点引用可以跳转到原消息」，之后回复行变为普通引用，点击跳转。
- **用户回复**：在任意消息正文中选中文字时，选区旁出现深色胶囊「引用回复」，点击加入一条草稿引用；可以引用多条消息的多段，重复的段落提示后拒绝。消息的悬停操作「引用」引用整条消息（前约 60 字）。Composer 按发出后的样子排列草稿：每段一行引用（↩、作者色盘 + 名称、「段落」、右侧 ×），下面是自动增高的无边框输入「回复这段…」，不用卡片或框；有草稿时主输入框占位变为「补充说明（可选）」。Enter 发送，Shift+Enter 换行；有草稿的回复为空时拒绝发送（「每段引用都写一句回复，或者移除它」）。已在草稿中的段落在对话中原位显示安静的点状下划线，直到发送或移除。
- **发出的用户回复**：气泡内每对是一行引用（与 Agent 回复行同样式）加回复正文，对与对之间只用约 12 px 间距分开，补充说明放在最后，气泡内不套框。点击引用行跳到来源并标记段落。通知和旧客户端仍使用带 `>` 引用的纯文本。

## 首次使用

新安装先登录 Zork 账号，再准备本机工作空间与模型，模型可用后直接进入 New Chat。首次欢迎文案留在 New Chat 中央，不另设完成确认按钮。已有可用模型直接跳过配置；需要配置时复用现有模型表单。引导中不提供设备选择或连接，只有一个对话目标时 New Chat 也不显示设备选择条；设备管理保留在日常设置中。

首次使用进度由客户端 core 持久保存。打开浏览器不代表登录成功，创建本机运行环境不代表引导完成；取消、失败和中途退出后从真实账号、运行环境与模型状态恢复。已有工作区不强制重走引导，账号登录不成为既有本地或 Mesh 工作的运行前提。

## 加载与等待

有缓存立即显示；无缓存的列表/对话、局部详情和前翻历史分别在所在区域显示加载。操作提交使用发起按钮内的反馈；文件保存显示实际写入阶段，目的地选择不冒充正在保存。加载失败不能显示为空集合。

应用启动不以设置页充当等待页。已有工作区保留导航与缓存，仅在依赖尚未准备好的设备区域提示状态；尚无可展示工作区时，使用专门的准备或首次使用页面。失败显示原因和重试入口；设置页的返回操作始终回到可显示的对话或首页，不能静默无效。后台恢复完成不覆盖用户等待期间主动选择的页面。

后台同步不遮挡内容。离线 outbox、授权、扫描和人工确认分别表达等待原因，不能统一成永久转圈。Session 执行状态使用自己的活动提示，不等同于消息初次加载。

指示器立即占位、延迟出现，避免短操作闪烁；仅可见且活动时调度，静止或离场释放计时。新旧请求按代次隔离，迟到完成不清除当前加载。共享符号与时钟由组件实现维护。

<a id="file-preview"></a>

## 附件与只读预览

草稿附件是输入框内、编辑区上方的一排胶囊：缩略图或类型图标、名称、类型与大小，以及常驻的移除操作；缩略图与胶囊同心。顺序即 core 的添加顺序，超出宽度时横向滚动，右缘渐隐提示还有内容。点击胶囊直接打开预览，没有先展开再打开的两步；添加和删除直接更新可见文件，不做形变或退场动画。读取中与读取失败写在对应的胶囊上，失败给出原因和重试；拖入文件时输入框显示落点，松开后与选择器、粘贴走同一添加路径。

输入框附件操作直接打开系统选择器。缩略图在后台按需缓存，界面绘制不解码全文或图片。预览可打开、移除或引用到新草稿，文件权威与固定版本见 [附件合同](shared-files.md#attachments)。

消息图片保持比例，长边不超过 320，极端长宽比才按既定缩略图规则裁切；连续多张图片组成两列网格，只在网格外角取块圆角。其他文件是块圆角的文件块：类型徽标、名称、类型与大小，点击即预览。获取中、来源设备离线与已撤权写在文件块自身，不显示假内容。只读图片使用单层浅暖灰画布：顶栏为名称、位置与尺寸、缩放、更多和关闭，两侧为上一个/下一个，底部是同一消息文件的缩略图条；保存与引用到新草稿在「更多」和上下文菜单中，不添加无关背景设置或文件信息面板。

关闭预览恢复焦点与阅读位置。复制和另存使用完整原文/字节；截断、编码失败、加载失败与不支持格式分开。代码可高亮、Markdown 可切换源码、SVG 可查看源码；系统首页/封面预览明确不是完整文档浏览或媒体播放。临时预览不修改原快照。

<a id="client-preferences"></a>

## 客户端设置入口

使用客户端默认文字与系统缩放，不另设自定义字号控件。桌面诊断只读取设备信息，复制报告包含版本、系统、检查时间和可达性，去除名称、地址、身份、凭据和 Chat 内容；About 显示实际编译版本与许可。账号入口在首次连接与设置中均可访问，且不依赖 Mesh 就绪，产品账号身份不等于 Mesh 或模型授权。

清空数据必须先说明本机范围、不可撤销及退出行为，再明确确认；取消不修改数据，执行状态由 core 管理，不因关闭页面中断。桌面清空当前客户端及其内置节点，保留独立 Station 和其他设备；先停止节点，待旧进程及写入者退出后完整移除存储，再以空白状态重启，中断恢复先于任何新存储打开。手机使用系统应用数据清理，退出后由用户重新打开，不删除电脑上的模型连接或 Chat。

<a id="mobile"></a>

## 手机端职责

手机连接已有设备、创建和参与 Chat，并管理模型连接，不托管 Station。手机登录与电脑相同的 Google 账号后自动接入；其它执行设备通过电脑生成的安装链接加入。

首页按消息时间混排所有设备的 Chat，以设备标识区分来源，顶部设备状态条显示各设备状态；新建 Chat 只有一个悬浮入口，设备在新建页内以标签切换。对话头部的成员入口进入执行历史，「更多」收纳文件与归档。消息始终完整显示。

设置分为「客户端」（账号、外观、通知、已归档的 Chat）、「Mesh」（按提供商汇总的模型连接、设备、连接设备）和「高级」（安卓调试、清空本机数据）。外观只选主题，字号跟随系统；不提供工具连接或消息折叠设置。服务按设备查看，资源入口不扩大管理或执行权限。保留移动端返回、触控和系统输入行为，不复制电脑节点运行设置或空占位页。布局与触摸尺寸见 [Android 界面基线](../../apps/android/design.md)。

通知见 [系统通知](notifications.md)，模型与账号规则见 [模型连接](model-connections.md)。

<a id="component-gallery"></a>

## 组件展台

Playground 用真实共享组件表达和验证交互；外壳本身也必须全部由组件库组成。缺少能力时先补共享组件，页面不复制控件、布局配方或装饰绘制。业务示例使用 core fixture，不能实现另一套规则。

复用指调用同一个完整组件，包含视觉状态、输入和焦点生命周期；页面传入内容、参数和回调。把另写的控件放进组件库、另加一组外壳专用 API，或只共享几何、内部按钮和正文，都不算完成。组件能力不足时完善原组件，或把原示例中的实现提取为公共组件，并让原示例立即改为调用它。

目录、示例工作区和参数面板各有职责：目录先区分基础组件与业务组件，再按用途选择家族；并发测试单独进入。项目使用的所有 UI 控件都必须有共享实现和组件库展示，包括基础控件、状态指示与完整业务组合。新增或修改控件时，同步补齐实际使用的状态和交互示例。展台传 mock 参数，项目传真实参数，双方调用同一个完整组件；视觉、交互、输入和焦点没有演示版与项目版之分。mock 适配提供同一参数和事件合同，不在示例中另拼控件，也不通过示例专用分支改变其行为。

基础组件目录参考 Radix 的职责与行为合同，外观和动效沿用 Zork 的共享组件与设计规则。已有源码、独立演示和完整键盘/可访问性合同是不同的覆盖层级，不能凭外观或业务组合认定组件齐全。核对结果随任务保存，不在设计文档维护实现清单。

示例用简短说明和真实操作展示状态与配置。示例默认在连续的白色无框画布中按标题和间距分组，不统一套卡片；组件保留自身表面。同组简短状态与变体合并为共享分段选择，不排列多个独立按钮；选项过多或文字较长、无法保持标准热区时使用选择器。状态选择与整页调参分别布局。

宽窗口显示独立滚动的目录和参数栏；空间不足时使用共享模态面板，不压缩文字或整体缩放画面。断点由真实示例最小宽度决定，工作区保持阅读密度和必要留白。

全部外壳使用共享文字角色、标准热区和普通圆角。无框预览按实际内容定高，保留矩形视口约束；组件内容使用平台原生裁切。

目录切换保留稳定示例实体与输入状态。参数上下限禁用，不循环跳回。采样期间锁定会改变条件的操作，结束恢复；无记录不能复制结果。菜单与模态支持键盘、滚动、IME 和返回焦点。产品窗口弹窗采用下方的 PlainDialog 面板与淡入配方。

<a id="static-controls"></a>

## 静态控件与浮层

桌面优先使用 GPUI、`gpui-base` 与 `gpui-component` 的按钮、选择、菜单、浮层和定位能力；Android 使用 Compose Material3 对应组件。共享层只定义 Zork 的颜色、尺寸、文案、组合与业务意图接线，不维护第二套轮廓引擎、路径命中或场景动画。普通圆角、描边和内容裁切使用平台原生绘制；控件的 hover、pressed、selected、focus、disabled 语义各自独立。

菜单与详情浮层按触发器的当前布局锚定，空间不足时翻转并在视口内限高滚动。动效的原则、时长、曲线和各场景写法见 [动效规范](../../apps/zork-design-pc/docs/07-motion.md)。Tooltip 直接显示、隐藏和切换内容或位置，不播放过渡动画；关闭立即移除不可交互内容，焦点按控件语义返回来源。`PlainDialog` 使用固定圆角面板和内容、背景淡入；开合中仍保持同一内容与焦点身份，减少动态效果时直接到目标。静止、离屏和后台不申请无用帧。

组件展示挂载生产控件和同一份状态接口，覆盖键盘、触摸、IME、焦点、禁用和长列表。性能验收使用真实页面与组件目录的输入和滚动，保留 8 ms 完整帧及 PlainDialog 中间帧要求；不使用旧的曲线路径或材料融合断言。

## Composer 演示

复用真实输入、附件预览条与 core Controller。提交由 core 接受并发布状态；界面不产生临时飞行气泡，也不从视觉转场推断送达。

演示等待、结果和文件预览明确属于本地 fixture。平台只适配选取和输入；选择文件名不代表已读取/上传字节，临时视觉元素不成为业务列表。
