# 共享界面设计

桌面沿用已确认的 Zork 设计，原始资源的来源和许可保存在 [共享资产](../../crates/zork-ui/assets/interface/README.md)。Android 的触屏几何与系统输入见 [移动端设计](../../apps/android/design.md)。产品归属、权限和操作结果来自 [core](client-core.md)，不在视觉规范再定义 API。

## 视觉与组件

保留暖白表面、墨色文字、品牌橙、动物头像和柔和圆角。颜色、文字角色、密度、间距与轮廓由共享组件持有；页面选语义与尺寸变体，不逐页拼普通 hover、边框和字体参数。新变体需真实重复用途，并同时提供示例。

所有小组件默认由内容与内边距决定宽度，由实际内容布局决定高度。除非设计合同或调用场景明确指定尺寸，否则不设置固定宽度或高度；内容、文字和语言变化后重新测量。容器填充、视口上限和动效布局不应把固定尺寸传回组件作为默认值。

文字按钮使用胶囊，桌面输入框使用 10 px 圆角、普通卡片和模态使用 12 px 圆角，选择浮层使用 16 px 圆角；短行与字段保留各自比例。普通图标操作 32 px、紧凑 28 px，Composer 为 24 px 操作和 14 px 图标。平台触控区不直接套桌面尺寸。圆角、描边和内容裁切由平台原生组件处理，约束见 [圆角规则](../../.agents/skills/zork-rounded-corners/SKILL.md)。

正文、说明和辅助信息有清晰角色及可读对比，不能用过浅文字制造层级。业务状态不只靠颜色。PC 客户端与 `zork-design-pc` 共用 Rust 组件，Android 共享语义并保留平台交互；系统授权页遵循其来源。

<a id="interaction"></a>

## 交互状态

- hover/pressed 是瞬态，selected/invalid/busy 有独立语义。选中与错误在 hover/focus 下仍可辨，keyboard focus 使用独立轮廓。
- 普通操作使用中性暖灰反馈，主操作保留其深色或品牌色语义；危险操作使用明确危险配方。pressed 不降低文字/图标整体可读性，也不改变字重、尺寸或内容位置。
- 字段 hover/focus 加强边框，底色稳定；invalid + focus 保留错误及邻近说明。文本链接用文字强调，不突然出现整行按钮底板。
- disabled 阻止反馈与激活；busy 保持几何并按操作语义处理重复输入。按钮禁用不代替 core 的业务校验。
- 热区与反馈范围一致，子元素不抢占根控件 hover。嵌套按钮不触发整行操作，仅局部可点的卡片不整卡亮起。
- 控件轮廓与选中态保持静态；减少动态效果直接到目标。触屏不能依赖 hover 才发现关键动作。
- 模态、菜单和组件示例共用焦点域，支持正反 Tab、Esc、系统 Back 与焦点恢复；IME 组合输入不被焦点快捷键误提交。

选择菜单沿用字段的文字、边框和焦点语义。下拉列表与模型选择面板使用独立的暖白静态浮层、16 px（手机 16 dp）普通圆角、细描边、柔和阴影和淡入；新建 Chat 的强度与模型/Profile 两层选择面板统一使用 24 px 普通圆角。填充、描边与阴影共用轮廓，来源不形变或转移材质。浮层按可用空间放在触发器上方或下方，列表过长时在浮层内滚动，不覆盖触发器或撑开表单。单选提交后关闭，多选保持展开直到用户主动关闭；空列表与禁用状态不可展开。触发器说明当前值和展开状态，选项保留选中语义。桌面客户端与 `zork-design-pc` 共用 GPUI 控件，Android 独立实现 Compose 控件和触摸尺寸；两端共享设计元素与 Rust core 的数值、业务合同，不共享 UI 组件。

## 导航与页面

Chat 层级来自 [导航合同](chat.md#navigation)。桌面导航为 32 px 行，使用普通 hover 和静态选中底色；键盘焦点独立可辨。分组留白、内容缩进不改变热区。

侧栏按像素拖动并持久保存，桌面范围 200–420 px；Chat 与设置共用宽度。Agent 消息头显示已知的设备名和模型名，不显示头像；缺少设备或模型事实时只显示已知身份。Composer 随内容增高，无手动拖高柄。页面标题、主操作、分区、字段说明与反馈位置复用组合组件。

桌面 Chat 正文完整显示，不按高度截断，不提供消息折叠设置或独立全文弹窗。跟随新消息时定位到该消息开头；用户浏览历史时保留阅读位置并提示有新消息。

新建 Chat 的灰色设备入口在有多个目标时显示于输入区上方，左右内缩，并由输入区的完整外轮廓遮住轻微重叠的接缝；只有一个目标时不显示。模型选择触发器显示当前模型与思考强度，静止时无底色，宽度随内容变化，高 28 px；发送按钮高 24 px。

模型设置是独立入口，按供应商展示各设备的 Profile 连接卡片；设备来源、订阅、额度、验证状态和模型数量都显示在卡片中，具体模型进入 Profile 后管理。设备不作为浏览前置选择；同名 Profile 保留各设备的独立连接，编辑写回所选来源；新增连接时才选择保存配置的设备。

表单失败或外部更新保留用户输入，列表更新保留阅读锚点与选择。显示实际对象身份和操作阶段，不从点击、网络断开或动画结束推断成功。

设备名称的展示统一携带 core 提供的连接状态，并复用设备名称与状态组件；文本型菜单和元信息沿用同一状态文案。区分客户端 Mesh 准备状态与目标设备可达性，本机 Station 已在线不能被显示成 Mesh 已就绪。状态更新随连接生命周期传播，不依赖当前打开的页面，也不把状态文字写回设备名称。

## 首次使用

新安装先登录 Zork 账号，再准备本机工作空间与模型，模型可用后直接进入 New Chat。首次欢迎文案留在 New Chat 中央，不另设完成确认按钮。已有可用模型直接跳过配置；需要配置时复用现有模型表单。引导中不提供设备选择或连接，只有一个对话目标时 New Chat 也不显示设备选择条；设备管理保留在日常设置中。

首次使用进度由客户端 core 持久保存。打开浏览器不代表登录成功，创建本机运行环境不代表引导完成；取消、失败和中途退出后从真实账号、运行环境与模型状态恢复。已有工作区不强制重走引导，账号登录不成为既有本地或 Mesh 工作的运行前提。

## 加载与等待

有缓存立即显示；无缓存的列表/对话、局部详情和前翻历史分别在所在区域显示加载。操作提交使用发起按钮内的反馈；文件保存显示实际写入阶段，目的地选择不冒充正在保存。加载失败不能显示为空集合。

应用启动不以设置页充当等待页。已有工作区保留导航与缓存，仅在依赖尚未准备好的设备区域提示状态；尚无可展示工作区时，使用专门的准备或首次使用页面。失败显示原因和重试入口；设置页的返回操作始终回到可显示的对话或首页，不能静默无效。后台恢复完成不覆盖用户等待期间主动选择的页面。

后台同步不遮挡内容。离线 outbox、授权、扫描和人工确认分别表达等待原因，不能统一成永久转圈。Session 执行状态使用自己的活动提示，不等同于消息初次加载。

指示器立即占位、延迟出现，避免短操作闪烁；仅可见且活动时调度，静止或离场释放计时。新旧请求按代次隔离，迟到完成不清除当前加载。共享符号与时钟由组件实现维护。

<a id="file-preview"></a>

## 附件与只读预览

草稿附件按 core 的添加顺序呈现为普通预览条。添加和删除直接更新可见文件，不做曲线开孔、纸面形变或退场物化。hover、固定展开、Esc 和外部点击不清空草稿。

输入框附件操作直接打开系统选择器。缩略图在后台按需缓存，界面绘制不解码全文或图片。预览可打开、移除或引用到新草稿，文件权威与固定版本见 [附件合同](shared-files.md#attachments)。

消息图片保持比例，极端长宽比才按既定缩略图规则裁切；文档保留可识别名称/类型及整页预览比例。只读图片使用单层浅暖灰画布，关闭/切换/缩放为直接操作，其余在上下文菜单；不添加无关背景设置或文件信息面板。

关闭预览恢复焦点与阅读位置。复制和另存使用完整原文/字节；截断、编码失败、加载失败与不支持格式分开。代码可高亮、Markdown 可切换源码、SVG 可查看源码；系统首页/封面预览明确不是完整文档浏览或媒体播放。临时预览不修改原快照。

<a id="client-preferences"></a>

## 客户端设置入口

使用客户端默认文字与系统缩放，不另设自定义字号控件。桌面诊断只读取设备信息，复制报告包含版本、系统、检查时间和可达性，去除名称、地址、身份、凭据和 Chat 内容；About 显示实际编译版本与许可。账号入口在首次连接与设置中均可访问，且不依赖 Mesh 就绪，产品账号身份不等于 Mesh 或模型授权。

清空数据必须先说明本机范围、不可撤销及退出行为，再明确确认；取消不修改数据，执行状态由 core 管理，不因关闭页面中断。桌面清空当前客户端及其内置节点，保留独立 Station 和其他设备；先停止节点，待旧进程及写入者退出后完整移除存储，再以空白状态重启，中断恢复先于任何新存储打开。手机使用系统应用数据清理，退出后由用户重新打开，不删除电脑上的模型连接或 Chat。

<a id="mobile"></a>

## 手机端职责

手机连接已有设备、创建和参与 Chat，并管理模型连接，不托管 Station。接入使用扫码/粘贴电脑邀请；生成邀请、批准其他设备和节点接入命令属于电脑端。

Skill 随执行上下文加载，历史 Agent 关联的 Skill 保留只读查看；服务按设备查看，MCP 展示获准的连接与定义。资源入口不扩大管理或执行权限。外观和通知管理本手机体验，保留移动端返回、触控和系统输入行为，不复制电脑节点运行设置或空占位页。

通知见 [系统通知](notifications.md)，模型与账号规则见 [模型连接](model-connections.md)。

## 组件展台

Playground 用真实共享组件表达和验证交互；外壳本身也必须全部由组件库组成。缺少能力时先补共享组件，页面不复制控件、布局配方或装饰绘制。业务示例使用 core fixture，不能实现另一套规则。

复用指调用同一个完整组件，包含视觉状态、输入和焦点生命周期；页面传入内容、参数和回调。把另写的控件放进组件库、另加一组外壳专用 API，或只共享几何、内部按钮和正文，都不算完成。组件能力不足时完善原组件，或把原示例中的实现提取为公共组件，并让原示例立即改为调用它。

目录、示例工作区和参数面板各有职责：目录先区分基础组件与业务组件，再按用途选择家族；并发测试单独进入。项目使用的所有 UI 控件都必须有共享实现和组件库展示，包括基础控件、状态指示与完整业务组合。新增或修改控件时，同步补齐实际使用的状态和交互示例。展台传 mock 参数，项目传真实参数，双方调用同一个完整组件；视觉、交互、输入和焦点没有演示版与项目版之分。mock 适配提供同一参数和事件合同，不在示例中另拼控件，也不通过示例专用分支改变其行为。

基础组件目录参考 Radix 的职责与行为合同，外观和动效沿用 Zork 的共享组件与设计规则。已有源码、独立演示和完整键盘/可访问性合同是不同的覆盖层级，不能凭外观或业务组合认定组件齐全。核对结果随任务保存，不在设计文档维护实现清单。

示例用简短说明和真实操作展示状态与配置。示例默认在连续的白色无框画布中按标题和间距分组，不统一套卡片；组件保留自身表面。同组简短状态与变体合并为共享分段选择，不排列多个独立按钮；选项过多或文字较长、无法保持标准热区时使用选择器。状态选择与整页调参分别布局。

宽窗口显示独立滚动的目录和参数栏；空间不足时使用共享模态面板，不压缩文字或整体缩放画面。断点由真实示例最小宽度决定，工作区保持阅读密度和必要留白。

全部外壳使用共享文字角色、标准热区和普通圆角。无框预览按实际内容定高，保留矩形视口约束；组件内容使用平台原生裁切。

目录切换保留稳定示例实体与输入状态。参数上下限禁用，不循环跳回。采样期间锁定会改变条件的操作，结束恢复；无记录不能复制结果。菜单与模态支持键盘、滚动、IME 和返回焦点。产品窗口弹窗采用下方的 PlainDialog 面板与淡入配方。

<a id="static-controls"></a>

## 静态控件与浮层

桌面优先使用 GPUI、`gpui-base` 与 `gpui-component` 的按钮、选择、菜单、浮层和定位能力；Android 使用 Compose Material3 对应组件。共享层只定义 Zork 的颜色、尺寸、文案、组合与业务意图接线，不维护第二套轮廓引擎、路径命中或场景动画。普通圆角、描边和内容裁切使用平台原生绘制；控件的 hover、pressed、selected、focus、disabled 语义各自独立。

菜单与详情浮层按触发器的当前布局锚定，空间不足时翻转并在视口内限高滚动。关闭立即移除不可交互内容，焦点按控件语义返回来源。`PlainDialog` 使用固定圆角面板和内容、背景淡入；开合中仍保持同一内容与焦点身份，减少动态效果时直接到目标。静止、离屏和后台不申请无用帧。

组件展示挂载生产控件和同一份状态接口，覆盖键盘、触摸、IME、焦点、禁用和长列表。性能验收使用真实页面与组件目录的输入和滚动，保留 8 ms 完整帧及 PlainDialog 中间帧要求；不使用旧的曲线路径或材料融合断言。

## Composer 演示

复用真实输入、附件预览条与 core Controller。提交由 core 接受并发布状态；界面不产生临时飞行气泡，也不从视觉转场推断送达。

演示等待、结果和文件预览明确属于本地 fixture。平台只适配选取和输入；选择文件名不代表已读取/上传字节，临时视觉元素不成为业务列表。

## 验证与运行入口

组件和页面按 [UI parity](../../.agents/skills/zork-ui-parity/SKILL.md) 检查实际输入、状态组合、几何与性能。展台运行与诊断见 [组件包指南](../../crates/zork-ui/README.md#playground)，不在设计规则里维护另一份命令清单。
