# 设备接入与节点生命周期

客户端、Station 与 Agent 是不同对象。客户端可以只访问已有设备；首次启动不自动启用本机节点或创建模型账户。Station 托管产品数据和执行能力，Zork 管理设备身份与成员关系，iroh 提供发现和加密传输。可选账号、发现和 relay 不成为全部数据或授权的唯一控制面。

安装、加入与升级步骤见 [原生节点指南](../guides/native-releases.md)。本文规定身份、信任和运行所有权。

<a id="invitations"></a>

## 邀请、成员与权限

邀请短时有效、一次使用，用途由服务端绑定；兑换在固定公钥的加密入口与设备密钥证明内完成。临时能力不开放普通管理接口。成功授权与恢复回执持久保存，重复兑换核对原身份；撤销成员后旧邀请不能恢复授权。

短票据携带端点公钥与随机 capability，连接后再交换名称、成员与网络设置。保留公钥是为了复用身份发现；单独随机短码需要额外映射服务。地址只是连接提示，不能代替身份验证。票据区分开发与正式环境，客户端在建立连接前核对所属环境。

手机登记为访问客户端；同一 Google 账号下的设备通过账号服务发现，并以设备私钥签名证明身份，由 core 自动接入。其它执行设备沿一次性安装链接加入，不自动把同账号 Station 合并。接入后 core 持续维护整个 Mesh 的设备目录和连接，不依赖当前打开的节点或页面；版本化目录与保存的设备同时提交，撤权立即停止对应连接，保留本机历史和草稿。

自己的 Mesh 邀请建立完整信任的成员关系；业务能力仍检查各自合同。客户端、Station 身份分开，访问端不成为 Worker。

成员目录由明确管理节点维护版本。新建邀请和成员变更需要该节点在线，既有成员的执行与直连不经过它。旧目录不能恢复已撤权成员；管理节点迁移须有明确协议，不从离线自动推断新管理者。撤权关闭该成员的已有控制流并阻止新访问，不能收回已交付数据或冒充远端工作已取消。

Agent 可以替用户接入新电脑：`mesh.invite` 沿客户端同一路径签发邀请，把一次性加入命令返回给 Agent，由它在目标电脑上执行或在用户发起的会话里交给用户；`mesh.invites` 只报告邀请状态（已生成、已使用及加入的设备、已过期、已撤销），不再返回命令，`mesh.revoke` 撤销未使用的邀请。所有已接入的会话入口（Zork 客户端、Slack 等 IM、主动绑定、委派任务）都可以发起：只有用户信任的 IM 才会被接入。命令就是 Mesh 准入凭据，Agent 不得把它转发到其他会话、工单或会向外同步的文件；可能泄露或不再需要时立即撤销。短时有效与一次使用仍由 Station 保证，Station 只记录发起的 Session 与标签，不保存命令。

切换和本机离开需要绑定当前目录版本的明确确认。切换在目标接入成功后才替换本机旧组授权，取消或失败保留原连接与数据；旧组目录留作本机恢复依据，不清空其它成员或手动关系。管理节点仍承载其它成员时不能直接离开。入组进度由操作所有者持久保存，进程恢复继续同一操作和身份，未知回执不以新身份重新兑换。

<a id="lifecycle"></a>

## 运行与退出

| 节点来源                     | 客户端退出后的行为               |
| ---------------------------- | -------------------------------- |
| 独立启动或脚本安装的 Station | 继续运行                         |
| 客户端仅连接已有 Station     | 保留原所有权和运行方式           |
| 客户端管理、未启用后台运行   | 控制连接结束后停止               |
| 客户端管理、已启用后台运行   | 系统服务接管已有进程，工作不重启 |

最小化、真正退出、后台运行和登录启动分别处理。启用以实际 readiness 为准；模型授权失败可显示为节点在线但模型不可用，不能仅凭开关显示就绪。

已启用的本机节点由客户端 core 在应用入口恢复，与建窗并行。应用持有运行时直至退出；替换窗口或组件不释放节点所有权，退出先阻止新的启动，再等待所拥有进程结束。

已保存工作区先从客户端缓存打开，本机节点与客户端 Mesh 独立恢复。Mesh 的对端恢复可能等待本机 Station，不能串行放在本机节点启动之前；远端不可达也不阻止本机使用。core 分别发布准备、可用和失败状态，重试不重复启动仍在进行的恢复。

设备密钥迁移保留原公钥身份，并沿用旧生命周期锁，防止新旧程序同时使用同一身份。传输不再启动文件同步引擎；业务同步沿自身 owner、epoch 和游标恢复。退出须关闭所拥有的连接、发现与代理任务后再释放生命周期锁。

本地 Chat 的读取、发送和 Agent 回复依赖本机权威与消息存储，不等待 Mesh 对端恢复；需要远端传输的操作仍沿 Mesh 就绪与授权约束处理。界面可输入或 Agent 已收到消息，不代表回复链路已可用。

后台网络探测中的同步平台调用不能占满业务执行器；系统证书校验的阻塞阶段须让出异步调度能力，保留原信任与拒绝规则。启动验收应覆盖探测并行期间的真实收发，不能只在网络探测开始前检查 ready。

supervisor 管理内嵌 Agent 的 Station；重启按原持久上下文恢复。退出/异常断连需回收所拥有进程与 IO，主动停止意图不能被当作崩溃重新拉起。访问已有独立节点不取得退出控制权，停止不删除身份、Profile 或历史。

卸载系统看护不等于停止现有进程；关闭后台运行先取得客户端控制，再撤销看护，避免所有权空档。系统服务的具体选项查 `zork service --help`。

客户端切换不迁移工作或工作目录，离线保留草稿、已同步消息和最后确认状态；停止须等原执行确认。工作归属与自动归档目标见 [Chat](chat.md)，本地偏好与模型凭据见 [设置](model-connections.md)。

<a id="android-debugging"></a>

## Android 调试

手机用户开启 Mesh 调试后，每台已接入的 Station 都可以连接，无需选择或绑定单台开发电脑。客户端为各台 Station 独立建立加密控制连接和反向字节流，Station 只在自己的 loopback 暴露 ADB 入口，多台可以同时连接。双方可以分处不同公网网络；手机无需公网监听地址。连接沿用有效 Mesh 成员身份，不能由 Agent 请求替手机启用。

系统调试开关、实际 adbd 协议可用性和电脑的 ADB 授权分别判定。蜂窝网络模式需要先通过 USB 激活系统的 TCP 调试，首次系统授权和重启后的再次激活由用户配合完成。关闭 Mesh 调试只回收桥接，不冒充已经关闭系统 adbd。

Rust core 拥有探测、当前可执行动作、重连和状态发布；Android 提供系统开关观察、设置入口和前台服务生命周期。页面只呈现当前需要处理的步骤，USB 命令和端口编辑放在激活说明中。手机就绪与每台 Station 的连接状态独立；某台 Station 等待授权、离线或重试不阻塞其他连接。

成员撤销或单台控制连接断开时，只回收对应 Station 的该代监听端口及全部流；关闭调试、改变手机端口或本机 adbd 失效时回收所有受影响的连接。旧代结果不能恢复连接。Station 自动把代理接入本机 adb server，Agent 直接通过 adb devices -l 发现；临时 serial 只在其所属 Station 和当前连接代次内有效，不能跨 Station 复用。

开发承载连接的应用时，保留稳定版作为连接宿主，使用独立包名的调试版。安装和启动完成分别验证；连接或构建成功不代表安装成功。操作入口见 [Android 指南](../../apps/android/README.md#mesh-adb)，Agent 通过普通设备命令执行已授权的调试操作。

<a id="discovery"></a>

## 发现与网络配置

同机 loopback、LAN mDNS、公开发现与 relay 只提供地址，不能建立信任。纯客户端与 Station 使用不同身份，并继续经过同一认证、成员检查和传输协议。控制 RPC、订阅和字节隧道直接使用原生 iroh ALPN，不发布或下载控制内容程序，也不回退到旧 socket 桥接。请求取消和运行时关闭回收其流、处理任务与监听资源。

同机地址缓存只有在对应进程的文件 lease 有效时才能用于连接；旧文件/端口不代表进程仍活着，读取与存活检查须绑定同一记录。临时端口不写成持久成员身份。已配对双方同时重启可使用先前认证身份开始恢复，不能互相等待对方的新快照形成死锁。

LAN 发现独立于同机缓存，按当前接口分别注册并处理运行期故障；增加、移除接口或重启无需固定某个地址。发现注册和代理监听归对应运行时所有，安装成功不结束错误监督。失败按 1 秒起、每 5 次增加 5 秒重试，稳定运行后重置，退出取消等待并关闭旧资源。诊断可分别关闭 `ZORK_MESH_LOCAL_DISCOVERY` 或 `ZORK_MESH_LAN_DISCOVERY`；显式 offline 仍允许本地与 LAN 发现。Android 平台只适配 multicast 生命周期，不裁决业务信任。

节点公布当前直连与 relay 提示，身份验证后才将提示用于该公钥的连接；端点变化通过成员目录更新，不能写成用户的本机 bind 或覆盖无关成员的新路由。HTTPS relay 和探测沿系统 TCP／显式代理路径；UDP QAD 使用端点自身的真实 socket 与独立解析器。QAD 来源只承担地址发现，不能成为转发 relay 的候选。

多网卡发现时，同一身份在各接口发布一致的完整地址集，查询在有界窗口内继续接收后到地址。邀请保留多个端点提示，不能由先到的虚拟网卡地址排除其余可达路径。

服务预设与用户配置分层合并，`ZORK_SERVICES_CONFIG` 可选择覆盖文件。relay 列表整体替换；offline 不被仅填写 URL 隐式取消。公开端点默认值由随产品构建的服务配置定义，文件中不放账号凭据。更换账号服务的 origin 或 Google 应用配置后重新认证，不向新服务发送旧凭据。

账号服务验证 Google 身份并提供同账号设备目录；设备注册还须验证该设备的私钥签名。设备私钥留在本地，iroh 验证连接对端公钥，本地有效成员记录决定业务访问。安装链接建立的成员与账号自动连接分别记录所有权，账号切换或退出不能撤销独立安装的成员。

控制面协调账号设备目录、签名发现、地址交换和不透明中继。签名发现记录绑定设备公钥并防止旧版本覆盖；中继不可解密端到端业务内容。公网中继不依赖 Google 登录，云端只执行共享服务的连接、流量及帧资源限制。这些限制约束可用性，不构成 Mesh 授权；云端失效不撤销成员身份或可用的直连路径。

账号管理和网络运行时分别拥有生命周期。退出账号撤销该账号自动建立的连接，保留独立安装或手动配对的成员；中继不依赖账号登录。凭据绑定签发 origin，仅用于账号服务，不传给其他设备或写入 Mesh 配置。账号变更拒绝迟到目录响应；退出先停用本地凭据，服务端确认后才表示远端会话已撤销。

账号入口不依赖本地 Station 或 Mesh 就绪。浏览器登录使用一次性请求和 PKCE，token 不经浏览器回调 URL；无界面设备可在任意浏览器完成可选账号登录。邀请解析和失败重试独立于账号状态，取消或替换邀请拒绝迟到结果。离线邀请从首次解析起保持直连模式。部署与操作见 [中继控制面指南](../../deploy/cloudflare/README.md)。

邀请可携带网络配置，首次访问端采用前检查已有关系和环境；Station 入组或切换保留已有网络选择，已有节点不因打开客户端就被重配。传输重建保留身份与数据。发现、直连和 relay 各自取证，看到 relay 流量不等于全部传输被强制中继。

<a id="compatibility"></a>

## 命名、升级与诊断

节点服务称 Station。旧数据和 wire 中保留的 station 名称不应机械替换：readiness 文件、序列化字段、macOS bundle 标识及授权枚举承载兼容身份。改可执行名称不迁移数据库、重写 ID 或轮换凭据。

开发与正式应用由安装元数据区分，数据目录在首次打开时固定环境，独立 helper 沿用该目录的环境。两套客户端、节点身份、偏好和成员关系分别保存，不能仅靠路径名字猜测或让开发包打开正式目录。邀请中的命令使用接收设备上已安装的 CLI，不嵌入发起设备的绝对路径或未发布的下载地址。

更新使用完整匹配的包与 bootstrap，不能只换一个新名称二进制。macOS 的正式安装、开发固定 app、临时测试包分别管理；具体打包与清理按 [验证规则](../../.agents/skills/zork-validation/SKILL.md)，不在这里复制机器路径或构建参数。

连接、恢复和后台接管按 [Mesh 诊断](../../.agents/skills/zork-mesh-diagnostics/SKILL.md) 选择测试。尤其核对重复接入、旧实例保护、双方重启、失效地址、成员撤销和 rapid relaunch；同机多节点不代替实际设备与网络环境。

<a id="identities"></a>

## 标识与凭据

新生成的项目实体、请求、回执及临时标识统一使用 ULID；已有标识视为不透明字符串，恢复和重试不重写 ID。外部服务 ID、Mesh 公钥、内容哈希、短邀请 capability 派生值和第三方内部 ID 保持各自协议。

ULID 的时间不是跨设备权威顺序，也不是访问凭据。访问凭据和 PKCE 使用 OS 安全随机字节，不因启动或命名调整自动轮换。新生成的管理、任务、浏览器和 Mesh 凭据使用 32 字节随机值；历史格式按其兼容协议保留。
