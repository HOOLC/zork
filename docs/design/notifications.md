# 系统通知

业务分类、去重、隐私、免打扰和点击目标由 core 持有；平台只申请 OS 权限、显示/撤销通知、报告接受结果与用户操作。Session 自通知、Chat 发言、系统通知与会话已读是不同事件。

## 事件与持久确认

- 新送达回复和需要处理的业务事件才进入提醒；用户消息、工具活动、流式片段和派工输入不触发回复通知。由 owner 生成，执行镜像不重复提醒。
- 首次完整目录建立基线，不对旧历史补发。断线补回按真实事件时间与保留规则筛选，过期事件丢弃；同会话突发合并为最新提醒，队列和已接受路由有界。
- 旧任务的 Review/失败可产生兼容提醒，解决后撤下；这不为新 Chat 增加完成或验收状态。
- 当前可见会话抑制系统提醒，包括正在阅读旧消息时。只有跟随可见尾部才按阅读规则推进已读；OS 接受、点击或任务完成不等于已读。
- 打开会话、静音、禁用、删除来源或撤权时撤下对应提醒。隐藏预览也撤下此前已显示的名称，平台不支持撤回时点击必须核对最新状态。

基线、待处理队列和偏好持久提交。OS 接受之后才确认；OS 显示与 SQLite 不是一个事务，重启按稳定通知身份核对，不能承诺用户恰好看到一次。瞬态错误有界重试，权限拒绝不在后来授权时补发过期通知。

发送前 core 重验授权和隐私。默认隐藏会话名称，正文只包含事件类别，不含消息正文、工具参数或凭据。点击使用持久节点/会话身份，启动后仍须拒绝已移除或撤权目标；不能把 task ID 当 Session ID。

## 平台边界

桌面客户端运行、最小化或窗口失焦时可接收；退出后停止自身订阅，远端节点继续工作不等于另一台 Mac 仍会弹通知。macOS 的 bundle 标识、Info.plist 与实际运行主程序必须绑定同一签名身份；裸二进制不能假装具有 app 通知能力。权限、测试、声音与系统设置入口沿平台能力呈现。

Android 默认不保持后台连接。用户开启后，由可见前台服务维持同一客户端运行时，通知观察不等待显示帧；普通页面仍按帧消费。宿主/服务实例身份隔离迟到退出。系统休眠、用户强停或厂商策略可能中断连接，重新打开恢复；独立云推送另见 [待决方案](../proposals/mobile-push.md)。

手机通知渠道和权限由系统最终控制。接受回执不改变已读；旋转、后台无 UI 帧、进程恢复和冷启动点击都按同一 core 投影处理。

## 验证

按 [验证规则](../../.agents/skills/zork-validation/SKILL.md) 分别测试 core 分类/账本、OS 身份与接受、实际横幅/声音及冷启动点击。Android 通知 fixture 只在独立模拟器运行；受控数据不代替设备后台到达率。
