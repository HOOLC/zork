# 共享文件与附件

文件有一个内容权威，Chat/任务/Skill 保存引用而不是平行字节副本。Synch 提供元数据、版本选择和 CAS 按需读取；客户端不逐 Station 查询后拼接另一棵目录。

<a id="spaces"></a>

## 空间与归属

文件共享使用独立的用户共享 Synch space，共享文件控制器直接查询这个 space，用户入口浏览其中的文件树。Station 业务文件、Skill 和内部控制各有独立来源；不先枚举所有 space 再排除内部项。通用文件 API 可按明确引用访问各 space，产品入口的查询范围由 core 持有。

用户共享文件的默认发布根是 `<data>/shared/`，新节点默认为空，只包含用户主动放入的内容。系统创建的工作区、仓库、作业、Session 记录和附件属于业务文件源；既有 `<data>/shared-files/` 路径及固定引用保持兼容，不自动搬动或重新归类其中的数据。Skill 来源是并列的 `<data>/skills/`。各 space 的发布根不重叠；用户共享根内任意新目录可自然进入文件树，目录名称不决定是否共享。空间分工是业务归属和导航边界，不是文件的访问权限。

当前 Mesh 成员完全互信，不新增 space 授权或节点私有隔离。来源默认不占列表列和设备标签，详情按需展开；core 始终保留 origin 与真实版本。面向用户的空间不映射成 Station 的完整数据根，也不预置 Session/运行文件等内部分类。

生产者在对应 space 的文件源发布数据；配置、凭据、身份、未完成 staging 和执行缓存留在对应非发布区域。space 的职责不决定 Station 的完整物理目录布局，也不引入映射全部节点文件的虚拟根。目录与引用调整不自动授权迁移、回填或删除旧数据。

## 版本与保存

相同 space/path/content root 保留多个来源，不同内容保留不同版本。默认沿 Synch 版本选择；预览、读取、另存和执行固定选定内容根，路径随后更新不能偷偷替换字节。

扫描器发布真实目录元数据，空目录的创建、改名、删除与权限进入同一同步流程。目录展示直接子项，符号链接和 socket 按底层元数据表达；不跟随链接逃出源根，不执行 socket。来源在线、访问端连接正常和内容已缓存是三个状态，缺少证据时保持未知。

保存由 core 维护选定版本与操作票据，平台只提供系统目的地或文档描述符。暂停/重建与更换授权来源分别处理；撤权使预览、在途结果、保存票据和未应用批次失效。已经导出到用户位置的文件不能收回。

内容先在私有 staging 完整验证，再原子发布普通文件，SQL 只记录固定引用。SQL 失败可以留下未引用的完整文件，不能留下指向半份内容的消息。同步 CAS 是网络副本，不成为第二份应用文件权威。

<a id="attachments"></a>

## Chat 附件与交付

附件逻辑归属 Chat，目标节点持有其权威快照；不要求先创建旧 Task。系统选择、拖放和粘贴在开始时绑定原设备/会话草稿，后续切换不改变目标。选择文件后固定内容，准备完成前不能让文字抢先发出。

同次发送的正文、附件和发送中状态写入同一本地消息，与草稿清空一起提交；本地提交失败保留草稿。手动重发遵循 [Chat 发送约定](chat.md#身份与消息)，附件沿用已选择的固定内容，不从后来变化的源文件重建。超出消息正文范围时 core 转成完整 UTF-8 文件，保留已有附件与文本语义；无法保存消息时不丢输入。

上传块保持有界，持久接收位置只表示连续完整前缀。重复内容幂等，不同内容复用 ID/偏移拒绝；最终验证完整 hash 与长度，消息只引用目标 Chat 已取得的完整文件。分块暂存及记账不触发业务变更，完成提交才发布。

源消息完整提交文件引用与作者，持久化后才发布，发送确认遵循 [Chat](chat.md#身份与消息)；公开封装不包含客户端绝对路径。跨节点发送固定目的地与确切文件，不能让对端随意读取调用者路径。Agent 使用同一文件引用，不永久导出第二份副本。

派工输入先验证并保存，再投递执行 mailbox；输入未到齐不能启动。回传文件绑定真实 executor、assignment 与来源引用，复制幂等并保留 provenance。图片可传输/预览不等于模型具备视觉输入，也不自动解析 Office/PDF。

<a id="skill-files"></a>

## Skill 文件消费

Skill 来源与自动发现见 [Skill 合同](agent-skills.md)。文件可显式读取，不代表应自动发现为 Skill。来源绑定可跟随更新；一次消费固定 origin 与已发布树的 snapshot，相对正文、资源、分页和物化继承该快照。文件 root 与目录 snapshot 分开，固定版本不可用时报错，不回退到最新。脚本需要本地路径时，物化该快照的整棵子树到私有执行缓存。

物化有范围和总量边界，活动执行期间不淘汰已返回路径；链接只在选中子树内部，socket 不变成可执行文件。执行位必须来自该版本的真实元数据，缺失时保留只读能力，不推测权限。同内容但不同 origin 的 Skill 仍绑定自己的资源来源。

<a id="file-browsing"></a>

## 读取与订阅

一个共享控制器观察现有 Synch 元数据，先订阅后读初值；查询不启动全量扫描或业务轮询。游标绑定 space、路径、来源、筛选、排序及该范围的真实变化，迟到记录也要使范围失效。

core 保留已加载范围，内容更新重建该范围，不退回首个页面，也不按页数重复扫描整棵目录。切换查询建立新代次，旧响应不能填回。目录、内容内存缓存、完整另存及执行物化分别有界；离线只读已取得内容，不声称所有文件都已下载。

Session 记录作为文件可按需读取，但不触发客户端历史数据库或隐式重放；压缩记录不在预览时自动全量解压。完整文件与有界文本/图片/系统预览分别表达，保存始终返回原字节。预览交互见 [共享设计](interface.md#file-preview)。

## 验证

按 [共享文件 skill](../../.agents/skills/zork-shared-files/SKILL.md) 和 [验证规则](../../.agents/skills/zork-validation/SKILL.md) 检查多来源同路径、版本固定、读取中更新、路径逃逸、任意新目录、取消信任、分块恢复、回执丢失及 Skill 物化执行。元数据查询、文件传输和可见列表呈现的性能分别测量，保留规模和完整性边界。
