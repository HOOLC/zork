# 数据一致性与恢复

UI 读取 core 管理的本地投影。本文规定数据权威、一致性和恢复边界。

标识、凭据与设备身份见 [身份约定](devices.md#identities)。

## 数据权威

| 数据                            | 权威与客户端边界                                                             |
| ------------------------------- | ---------------------------------------------------------------------------- |
| 设备、Agent、Profile 的公开目录 | 所属 Station 裁决；客户端保存授权后的副本，地址和显示名不是身份              |
| 已送达 Chat 消息                | 源消息 append-only；core 可更新派生交互缓存，旧分页不能覆盖新结果            |
| Session 执行记录与统计          | 执行节点保存；概览来自 snapshot，详情按需进入 core RAM，不建客户端历史数据库 |
| 草稿与待处理意图                | core 持久保存；未解决意图不能作为可重建缓存淘汰，编辑不等待网络锁            |
| 在线、活动、额度                | 保留来源、采样时间与可用性；未加载、失败和空集合分别表达                     |
| 文件                            | 沿 [附件](shared-files.md) 的固定引用、完整保存与校验合同，不同步目录树      |
| 凭据                            | 沿专用认证和存储合同，不进入公开目录投影                                     |

不同对象可有不同 owner，跨 owner 视图最终收敛。离线副本不获得代替 owner 裁决业务的权限。同一 owner/范围复用协调器，网络响应先提交到 core/本地副本，再发布订阅；页面不维护第二套可写业务列表。

## 提交与游标

- 同库业务、投影、适用回执和水位在一个事务中提交。文件配置与 SQLite 不能假设原子写入；外部来源失败时保留旧值并标记不可用，不能发布成空集合或阻塞其他目录同步。
- 相同对象输入幂等，旧 revision 不覆盖新事实。缓存淘汰不是业务删除，普通分页未出现某项也不是 tombstone。
- 游标绑定 owner、epoch 和授权范围。源日志跳号可能来自授权过滤；UI applied version、消息位置和对象 revision 不充当同步游标。扩大范围必须补齐新增部分。
- 每次导出固定同一提交视图；分页同时受记录数与字节预算限制。客户端持久暂存，完整批次才提交实体、删除记录和游标。重复页、载荷变化、错误 owner、旧版本和页序都须校验。
- 增量保留对象最新版本与 tombstone。保留边界之前的游标要求 reset；冻结导出有数量和时间边界，不能无限占用读事务。
- 导出、回执和游标记账不广播业务失效。同设备/范围刷新合并，进行中的请求之后产生的新需求仍要追赶；持久水位已覆盖的提示不重复拉取。

## 命令与未知结果

需要可靠提交的业务使用持久命令 ID、目标 owner/epoch、基础版本及回执；不能从通用同步能力推断所有写接口都已支持离线执行。

客户端先保存意图及尝试状态。服务端将同库业务变化与回执一起提交；同 ID 同载荷返回原结果，不同载荷复用 ID 必须拒绝。丢失 ACK 后查询原回执，不能自动换 ID 或再次执行。单对象回执可更新该对象，不能推进整个目录水位。

持久接收、业务提交和外部执行完成分别表达。超时不证明未执行；任意外部副作用不承诺 exactly-once。冲突保留用户输入，未知效果按原调用核对。聊天失败后的重发遵循自己的投递规则，不因引入同步协调器而自动重试。

## 重建与撤权

- 普通重启保留 epoch；恢复旧数据必须建立新 epoch。独立已发水位可检测 SQLite 单文件回退；如果整个数据目录连水位一起恢复，恢复流程仍须主动更换 epoch，不能依靠同时回退的文件自动发现自己已回退。
- 已发水位在游标、数据页或回执对外发布前持久保存；仅供失效判断的版本提示不推进客户端游标。普通启动校验回退，不把尚未发布的新版本改记为已发。
- 投影 schema 升级只重建派生数据，并使旧导出/游标失效。业务表、身份、回执、文件权威和不属于投影的触发器不能一起清空。
- 撤权增加授权代次，清理对应公开副本与下载缓存。旧连接迟到的页和回执不能跨越代次；草稿、未确认消息和其他未解决意图保留。
- 日志保留、下载缓存与固定离线保留各有容量和生命周期，不把某个日志上限当作整个客户端的空间配额。跨端草稿、已读或离线写入需自己的冲突规则，不默认采用最后写入者覆盖。

## 消息范围与缓存

本地消息与发送状态遵循 [Chat 发送约定](chat.md#身份与消息)。已接收源记录按源节点、会话和消息身份保存，保留源顺序；未取得源位置的本地消息不参与源分页边界。回推或补拉更新对应本地消息的状态与源元数据，和读取范围一起提交；重复页不回退已归并结果，不能补造未知源区间的顺序。

先订阅再追赶至最后确认的源锚点，刷新不能只合并最新一页留下缺口。只有 core 成功保存并应用接收批次后才推进重连锚点，传输层读到或入队不算确认；失败从已应用锚点重新补拉。最早读到的源记录包含被折叠的交互结果，整页无可见消息也要推进读取边界；历史页和实时页交错时保留较早边界。core 自用的缓存游标不发给 Station，消息位置也不充当目录同步版本。

不可变消息源与可更新的派生交互缓存分开，结果先到和迟到请求不能覆盖新结果，详见 [用户参与](user-participation.md)。旧消息缓存迁移事务化，失败保留原值，待发送行不能迁成已送达。

会话强引用和内容估算有界；外部活动引用继续有效，无持有者时结束 IO。未确认本地发送由 core 持有接收兴趣，页面关闭不丢失迟到确认；确认或移除本地失败消息后释放这份兴趣。淘汰内存不删除已入库消息，再次打开先读本地页再追赶；不能因磁盘有历史就永久保持每个 Chat 的连接。

## 变化通知与空闲

通知来自有效业务提交、原生文件变化或进程事件，不能按 HTTP 方法/路径猜修改。相同内容、回滚、导出缓存、回执及水位内部记账不产生业务唤醒。业务投影和水位在同一提交边界改变。

共享 source 供进程内、SSE 和认证 Mesh 使用。先注册兴趣再读取，读取前建立变化检查点；读期间的新变化不能丢失。快照通知可合并，日志页须持续排空；各来源轮转，任一来源关闭须明确恢复，不能静默只剩部分来源更新。

发送队列位置与接收端持久游标分别推进；只有数据提交后才能更新重连位置。队列满时不读下一页、不推进未发送位置，但仍处理权限失效和绝对到期。瞬态事件溢出明确 resync；Session 状态重新取得 snapshot，详情另行请求。

通知版本/change token 只用于判定失效，不能持久化为业务游标。范围、owner 或 epoch 改变时校验恢复基线；只读观察允许自动重连，业务命令不得混入自动重连以致重新执行。

配置文件协调先监听再读取，并观察父目录的原子替换/重建；读取不触发协调。精确范围监听不扫描全部仓库或 Session。注册/读取失败保留最后有效值并有界退避，健康状态不进行周期性全量校验。

无新变化时内部同步停止业务查询。心跳只验证连接，不读业务状态；外部供应商要求的授权/额度采集、倒计时、保留回收及账号设备发现各有独立语义，不能因此宣称整个系统零轮询。

消息到达动画由 core 的独立序号驱动，历史恢复、分页、重连追赶和重复回执不产生新到达。订阅从当前序号开始，合并更新保留累计数量与有界提示，UI 不比较历史末条消息猜到达。

## 验证

恢复、重复/乱序、撤权、文件替换、背压与空闲收敛按 [同步 skill](../../.agents/skills/zork-sync/SKILL.md) 检查；core→UI 的已应用版本见 [状态订阅](state-subscriptions.md)。存储查询、通知分发、状态转换和实际呈现分别测量，历史跑分不证明新构建。
