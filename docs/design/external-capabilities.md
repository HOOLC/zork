# 外部能力

资源按所属设备和使用场景进入 Chat 或设置。有效 Mesh 成员互信；身份认证和成员移除仍然生效，不再增加逐节点 client、collaborate 或逐资源 share 授权。登记成功仍不等于进程或连接已经就绪。

## 能力提供方

| 提供方   | 持有的能力与状态                                                         |
| -------- | ------------------------------------------------------------------------ |
| Station  | 设备命令、MCP 连接、服务登记及执行回执；凭据和进程属于该 Station         |
| 客户端   | 用户浏览器、登录资料与客户端浏览器控制状态；客户端可以只连接远端 Station |
| 共同边界 | 认证主体、明确目标、原调用身份、取消和未知结果；传输不改变业务所有者     |

本文回答如何授予和调用外部能力。持久文件版本见 [共享文件](shared-files.md)，界面布局见 [界面规范](interface.md)。

## 工具与身份

Agent 先发现目标并检查可用能力，再准备依赖、安装和验证实际调用。工具操作手册由 `tool.help` 提供，Skill 提供最佳实践；具体分工见 [Skill 内容职责](agent-skills.md#content-boundary)。Skill 本身不授予它描述的设备或服务权限。

目标使用认证节点身份；名称、路径和程序属于该目标设备。调用者、Agent、Session 与 invocation 从可信上下文注入，模型不能指定另一个身份。实体 ID、配置 revision、工具 binding revision 和访问凭据分别使用。

普通执行与 MCP 调用由原工具保持 pending 至业务终态；取消沿原 invocation 的 `tool.cancel`，输出按返回的文件引用读取。模型不再维护旧 status/read/recover 轮询。回执、去重和恢复属于内部适配层，未知副作用不能因断线或重启自动重做。

执行不套通用整段期限；连接、锁等待、容量与终止确认分别有界。长期服务启动和派工有自己的接受/就绪边界，不能等待整个服务或 Worker 退出才返回，也不能把接受回执当作最终效果。

<a id="mcp"></a>

## MCP

服务由安装它的 Station 托管，身份是节点与稳定服务 ID。stdio 与 HTTP 都使用该模型；同名实例不静默切换账号、节点或故障转移。配置和凭据留在服务节点，登记成功不证明程序依赖或连接已就绪。

管理入口按安装清单、搜索、检查、安装、更新与卸载组织，执行统一使用调用入口，不另设配置读取、连接探测或启停工具。检查同时返回配置与连接/工具信息；停用、繁忙或连接失败时仍可读取配置进行修复。更新只替换提供的顶层字段，省略项保留；传输配置整体替换，启停是配置变更，并发更新使用当前版本。

启用的 MCP 对有效 Mesh 成员可用，使用安装时绑定的账号；不另设 share 或调用 grant。目录标记未响应节点的部分失败。工具定义按需取得，配置和定义版本改变后重验，不能截断 schema 继续调用。

有状态连接按主体/Agent/Session/服务隔离。调用前与返回结果前检查成员身份和服务状态，资源与回收有界；进程隔离和资源限制不自动构成 OS 沙箱。停用阻止新调用，原调用方读取终态仍须获准。

共享整个 Mesh 意味着当前及未来有效成员可用安装时绑定的账号；它不是每个调用者自己的第三方身份。secret_env/secret_headers 引用服务节点的秘密来源，目录、日志和结果不返回凭据。

原 invocation 驱动持久去重；派发前记录状态。丢失结果或无法确认取消效果时保留 outcome_unknown。结果正文可过期，去重记录不能提前淘汰使旧 ID 重新执行。保留 MCP content、structuredContent 与 isError 的语义，远端文件 URI 不自动映射本机文件或抓取外链。

协议版本、配置示例和默认上限查 [runtime](../../crates/station/src/mcp/runtime.rs) 与 `zork mcp --help`；未协商支持的版本/扩展明确拒绝。

<a id="desktop"></a>

## 桌面控制

桌面能力由设备上已登录图形会话的宿主进程提供。macOS 把屏幕录制与辅助功能授权绑定到宿主 app 的身份，因此驱动必须位于签名包内并由该宿主启动；授权仅由用户显式启动宿主的权限申请入口；模型调用不弹权限提示。授权缺失时明确失败，不静默降级为只读。Station 只连接它的本机 socket，不持有桌面授权，因此无图形会话的节点仍可运行，只是该设备此时没有桌面能力。

每次独立调用在发送业务动作前重新发现或启动同一签名宿主，并校验当前进程代次；宿主正常重启无需重启 Station。握手与业务动作保持同一连接，动作发送后丢失回复只返回结果不明，不自动连接新代次重放；后续独立调用可恢复。驱动版本或身份不匹配时明确失败，不回落到其它设备或借用其它宿主的授权。Station 使用带版本与进程代次检查的本机 IPC，不安装或调用 MCP。截图只暂存到 Station 私有临时目录，不进入 Station 的 HTTP 正文，再由既有工具图片通路交给模型并清理；转交失败必须作为工具失败返回。工具与参数清单由运行时契约维护，本文不重复。

macOS 打包可通过 `scripts/build-cua-driver.py` 从固定源码修订与锁文件生成运行产物，再交给 `scripts/package-macos-client.py --cua-runtime`。签名的 `ZorkDesktopControl.app` 与桌面主应用、Station 使用独立 bundle 身份；dev/release 前缀分开。宿主遵循候选 App 的最低系统要求与 GUI 架构，打包前检查 driver 的实际 Mach-O slices 和部署目标，不静默提高或降低候选平台要求。用户在需要时运行 `open -a /path/to/ZorkDesktopControl.app --args --request-permissions` 并在系统设置中授权该宿主；不授权 Terminal 或 Station 来代替。无宿主的 headless 安装仍可运行，桌面工具明确报告不可用。

<a id="services"></a>

## 服务与共享链接

Agent 通过普通 shell/job 管理自己的进程；服务登记只把现有监听地址映射为稳定 Mesh URL，并提供客户端应用入口。登记不夺取进程、不伪造就绪或日志，也不增加另一组进程启停和分享工具。历史托管记录继续按已保存的意图恢复，避免升级改变正在运行的用户服务。

服务停止后链接明确失败，登记和历史消息引用继续保留。重启后的存活由进程所有者负责；使用相关工具前查询 `tool.help`，共享策略与交付实践见内置 [service-sharing](../../crates/agent/skills/service-sharing/SKILL.md)。

`zork://service` 引用不是绕过授权的 bearer token。客户端以 loopback 入口通过认证 Mesh 双向字节流访问，HTTP/WebSocket 不包成逐块业务 JSON。每服务独立 localhost 域，校验 Host、Origin 和 Fetch Metadata，不给 WebView 任意本地文件或原生 bridge。

成员移除、停止或重启关闭对应流。服务写死的 localhost、Cookie Domain、HMR 和重定向不会自动改写；共享访问不承诺保留临时端口下的 localStorage，跨站登录需自己的适配。

<a id="publication"></a>

## 应用、页面与详情

服务登记产生持久应用入口，页面不再单独发布。普通网页通过 Chat 中的 Markdown 链接交付；Rust core 在消息入库时提取 HTTP(S)/服务链接并维护聊天内容索引，排除代码、图片源、可执行协议和内嵌凭据。新消息只提交自己的链接，分页可补入旧消息，源切换清除旧派生项。

对话文件和页面来自实际消息，不把整个工作区或资源目录混入聊天内容。已有发布记录与历史引用保持可读，不因工具删除而丢失用户数据。

资源详情按需读取，失败保留旧值与错误，撤权清除并隔离在途结果。公共摘要不泄露 MCP 启动配置或凭据；Skill 文件只读所属资源范围，服务日志不是任意文件读取接口。core 负责聚合、查询、缓存与操作，UI 只保留选择、滚动和展示缓存。

<a id="browser"></a>

## 浏览器与用户接管

页面和登录资料属于展示端客户端，执行 Agent 可以在别的设备；客户端无需托管 Station。使用独立浏览器资料，不复制系统浏览器 Cookie。普通网页不接入 Zork 业务 IPC。

用户消息携带由客户端连接提供、接收 Station 附加路由来源的 client_id；client.browser 按该身份操作客户端，独立于当前聊天和 Agent 的执行设备。浏览器标签仍可按聊天组织。用户接管关闭客户端控制，迟到回执不能恢复；重新开启使用递增代次，旧连接与秘密失效。

重试使用原调用与参数，持久回执避免重复点击；超时和进程重启后未确认的请求不自动再次执行。私有控制与网页安全、沙箱、系统钥匙串边界各自保留，不能用浏览器属性伪装代替兼容性。

同一 Chat 重开相同交付页面可选中原标签，收起面板保留页面但停止无用画面工作。关闭最后一个网页回收浏览器引擎，再打开可重建；这不停止共享服务或 Station。执行历史保持原生视图，切换网页与历史不重新加载网页。

新旧浏览器进程和控制连接按代次隔离；启动失败先回收所拥有进程，退出正常刷写资料并有界清理。macOS 需要图形安全会话、正确嵌套资源和稳定签名；单独组件能启动不证明完整包可用。平台分发和登录实际兼容性分别验证。

## 验证

按 [验证规则](../../.agents/skills/zork-validation/SKILL.md) 选当前节点工具、MCP、共享服务、资源和浏览器测试。检查实际效果次数、同名实例、主体隔离、取消/重启、旧回执、撤权和进程回收；画面、输入/IME、网页安全与帧性能另行取证。现有目录和 CLI 帮助提供具体入口，不维护第二份路由表。
