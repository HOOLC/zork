# 插件系统决策稿

这是待实施方案，尚无运行时或设备验收。目标是一份插件包在 PC 与 Android 本地运行，功能、业务结果、错误和权限语义一致；手机不依赖在线 PC 执行插件逻辑。PC 首版面向 Windows/macOS，Linux 保持同一契约。

## 已确定的边界

- 第三方计算使用独立 WASM 实例，默认进程内、UI 线程外执行。原生动态库、任意宿主闭包和未经限制的系统调用不作为普通插件入口。
- 包包含 Wasm、manifest 和资源，按内容摘要安装；声明能力不等于获得授权。检查路径、解包体积、模块边界和兼容性后激活，不执行任意安装脚本。不同设备安装同包与自动跨 Mesh 分发是两种能力。
- Zork 数据仍由 core/服务端持有；插件私有状态按安装与授权范围保存，不另建可写消息、配置或权限副本。资源经有界句柄访问，不把 PC 路径、Android URI、token 或 Cookie直接交给 guest。
- UI 能力应覆盖编辑器、节点画布和时间轴。标准 Button/List/Form 是便利封装，不能作为有限白名单，让每个新控件都要求宿主升级。

## 执行与 UI 分工

同一包包含两个逻辑角色，使用独立实例和可变内存；编译代码可缓存共享：

| 角色 | 责任 |
| --- | --- |
| 业务实例 | core 调度插件规则、状态提案与 effects；权限和 Zork 操作仍经原有业务边界 |
| UI 实例 | 呈现运行时调度布局、交互预览和动画；消费只读业务投影，显式事件提交业务意图 |
| 共享呈现运行时 | 稳定节点、布局/测量、事件协调、场景事务、资源与局部失效 |
| 平台适配 | GPUI / Compose 壳、原生绘制、文本输入、系统能力与可访问性 |

鼠标移动、滚动与动画不进入持久业务队列。UI 的 render/layout 阶段不能写业务；关闭界面、Activity 重建或回收 UI 实例不能丢失 core 已接受的操作。core 不依赖帧时钟或平台组件。

## 业务事务与恢复

命令带稳定身份，先持久接受，再在无数据库/全局锁的条件下计算。完整输出经长度、类型、状态基线与授权校验后，将私有状态、effects 和处理结果一起提交；只有事务成功才派发外部操作。emit 后 trap、缺结果或重复输出不能留下半次提交。

基线变化时有限重算，持续冲突保留输入并返回冲突。外部操作继续使用自己的预期版本和幂等 ID；一组 effects 不构成跨服务原子事务，有依赖的操作由前一结果推进。结果丢失按原 operation 恢复，未知效果不能因实例重启而重放。

呈现或实例失败不回滚已发生的业务效果。runtime generation、surface generation、私有状态 revision、业务游标、消费者 applied version 和 operation ID 各自独立；重建使旧计算/动作失效，已接受操作仍继续入账。

升级先在隔离副本上迁移状态，成功后原子切换包与 state schema；迁移不能产生 effects，失败保留原包/状态。有未决业务操作时推迟不兼容 schema 升级。旧结果即使缺少插件也能由宿主读取正文与附件，不为看历史自动执行陌生插件。

## 场景、输入与资源

一次场景提交把结构、布局、绘制、命中、可访问性、文本几何和弹层锚点绑定到同一版本。先暂存和完整校验，再原子挂载；不能画面移动而点击仍落在旧位置。依赖增量按消费者已应用基线合成或 Reset，只有自足的完整场景可以丢中间帧。

共享布局语义，平台提供与实际绘制一致的文本测量。字体、方向、语言、宽度和系统缩放参与缓存键；批量测量，限制反复失效，超预算保留上一份一致场景。列表、文档与二维画布使用可见区和有界预取，版本化文本/路径/图片只传变化部分，不逐图元 JNI 往返。

标准组件、通用布局和自绘必须可嵌套，画布内可编辑文本，图形上可锚定宿主菜单。二维应用界面是共同目标；GPU shader、三维、视频、外部 native view 和完整浏览器需要独立能力合同。

事件统一 pointer 身份、坐标、捕获/目标/冒泡、焦点域与手势仲裁。下/上/取消和有序编辑可靠保留；移动采样可以合并。普通反馈和已声明机械交互由宿主即时执行，不能同步等待任意 guest。删除节点、失焦、暂停或故障时释放捕获。

动作绑定在对象、参数或授权变化时失效；颜色/进度刷新不应使正常点击过期。提交携带当前字段值，旧 edit 回执不能覆盖新输入。Back、关闭面板和业务取消分别处理。

文本会话明确文档版本、UTF-8/UTF-16 索引转换、grapheme、选区、IME 组合、撤销和光标几何。系统输入法读取宿主的已确认编辑镜像，不等待 WASM；外部更新不能隐式提交组合输入。业务文档/持久草稿与控件未提交输入有明确提交边界。

自绘同时提供语义节点和动作，菜单/对话框复用宿主焦点与安全区规则。跨插件不能抢夺焦点或覆盖系统信任界面；Android 的虚拟可访问性层级、触屏替代操作和系统返回须实际验证。

## 故障与生命周期

运行时必须显式启用可中断执行及资源限制。异步 timeout 不能抢占同步 guest；fuel 也不打断阻塞 host call，不能换算成跨设备通用毫秒上限。guest memory、宿主分配、图片、队列、代码缓存和整个进程内存分别有界。

非法指针先做溢出/范围检查，复制后不保留 guest 裸指针；解码、布局和绘制工作量也有界。WASM trap 隔离不保护错误的原生宿主或引擎自身；如需覆盖原生 abort，再评估进程边界，而不是宣称 catch_unwind 解决所有故障。

实例之间公平调度，坏插件不能占住停止、错误反馈或正常输入。失败进入独立故障状态，有界恢复，主动停用不被自动拉起。Android 在提交时保存状态，不依赖 onStop；回收不可见实例后从持久记录/Reset 恢复，不把整片 Wasm 内存放进平台保存状态。长任务交给已有持久执行节点，不承诺手机退后台后持续本地执行。

## 待决定与验证

尚不冻结公开 ABI、编码、renderer、布局引擎、WASM 后端和预算。Core Wasm 与 Rust SDK 是起点；Wasmi 是便携基线候选，必须同真实复杂 UI 的其他后端比较。GPUI Web 依赖浏览器运行环境，不能直接当作普通 WASM runtime 的原生 UI 适配。原生宿主原语、自绘和 Web UI 应在同一需求上比较，最后收敛一套生产路线。

同一个包至少在 PC/Android 验证：约 1 MiB 文档的 IME/选择/虚拟化；节点画布与就地输入、跨区域菜单；时间轴双轴滚动与局部更新；正常实例与无限循环、越界、畸形场景实例并行。另测一万条记录、每秒百次变更、慢消费者恢复、操作丢回执及升级失败。

记录冷/热启动、输入到可见反馈、WASM/布局/文本/JNI/绘制成本、总内存及无变化唤醒。Android 包含旋转、字体缩放、进程回收与支持的 OS 页大小；缺少平台就明确未验证。小表单或空 Canvas 跑分不能证明完整 UI 能力。
