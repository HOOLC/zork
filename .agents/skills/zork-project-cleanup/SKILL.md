# 项目清理

遵循 [仓库内容边界](../../../AGENTS.md#repository-content)，只处理用户要求的范围。文档清理不扩展为源码重构、依赖升级或运行数据清理。

## 判断与执行

- 用 `rg` 和 Git 状态核对候选、实际消费者及未提交改动。删除前重新检查是否变化，保留独有信息和可恢复副本；无引用、年代久或体积大不能单独证明无用。
- 文档先分设计、提案、指南，再按持续的读者需求决定是否独立成篇。同职责内容去重合并，不为篇数硬合，不把旧台账搬到别处。
- 保留必要决策、兼容承诺与操作方法；接口细节查源码和生成帮助，进度/结果随任务或产物保存。方案完成后只提取有效决策，历史标签不等于永久保留。
- prompts、内置 skills、固定 fixtures、资产和许可证按功能输入判断。测试借用开发文档作样本时，优先复用固定 fixture，核对类型、规模和原断言。
- 移动/合并后按消费者位置更新链接、符号链接和展示别名，生成页与源同步。删代码/依赖前查调用方、平台、feature 和兼容承诺，依赖变更遵循 [构建规则](../../../docs/guides/rust-builds.md)。

## 产物与数据

生成产物只清理本任务创建、可再生成且无进程使用的部分。固定当前 app、正式安装、用户数据和其他任务产物按 [验证 skill](../zork-validation/SKILL.md) 保留；挪动目录不算释放空间。

运行数据须在用户明确要求的范围内处理。核对持久会话绑定、服务工作目录和恢复意图，不能仅看目录年代或当前打开文件。先停止相关运行、解除旧关联，再清理依赖记录；保留外键约束，并核对未用外键表达的通知、收件箱、消费水位和 epoch，按原协议保持一致，不盲目归零或重放。结束验证受影响业务能继续工作；节点 ready 和外键完整性不能代替投递恢复检查。配置和身份按授权范围保留。

## 验证

文档检查结构、路径、引用和展示一致性；代码/依赖按受影响行为验证。确认没有残留消费者，统计注明范围，交付说明删、合、保留的理由。最后按 [skill 维护](../zork-skill-maintenance/SKILL.md) 检查相关规则。
