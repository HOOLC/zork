# 关键门禁

只把用户明确批准“加入关键门禁”的要求纳入 smoke suite。普通需求、建议、审查发现和已有测试不会自动成为关键门禁；同一会话已有明确批准时直接执行，不重复确认。

## 批准与维护

- [smoke 入口](../../../scripts/smoke-critical.py) 的 `GATES` 保存已批准要求及验收口径，是门禁清单的唯一来源；`--list` 查看清单。添加、删除、放宽阈值或缩小验收范围都需要用户明确批准。
- 每项用稳定 ID 绑定真实 smoke test。沿实际产品启动和操作链验收最终可用状态；端口打开、进程存在或测试接口接受请求不能代替业务就绪。
- 测试失败应返回非零退出码并保留原因、实测值和产物标识。每项独立执行，缺少某项产物不阻止其余门禁，但该项须记为未验证、总体不能通过；不改阈值、伪造 readiness、预启动被测服务或挑选最快样本取得通过。
- 新增门禁时，测试已落地与产品已达标分别报告。实测未达标就明确保留失败；修复范围按当前任务执行，不把测试存在当作要求完成。

## 执行

代码交付及合并、发布验收运行全部已批准 smoke。仅文档或 skill 文案变化做定向校验；smoke 实现变化必须验证其成功、失败判定和真实运行行为。

先按 [验证规则](../zork-validation/SKILL.md) 重建并准备本次产物，再运行：

```sh
python3 scripts/smoke-critical.py --list
python3 scripts/package-macos-client.py --run python3 scripts/smoke-critical.py --app '{app}' --frame-binary /path/to/release/zork-gui-render-bench
```

已由当前任务重建并打包时，可以直接传该 app，避免重复打包。构建配置、系统和输入随报告记录；开发构建、release、进程冷启动与重启系统后的磁盘冷启动证据分别说明。

帧门禁使用原生完整组件与 Metal 完成时间。先核对被测完整组件、视觉配方及实际启用的渲染路径是否对应已批准要求；同一仓库的新构建或普通客户端场景不能代替新动效路径的覆盖。按构建环境指南用锁文件构建 release `zork-gui-render-bench`（features `native-blur-bench,frame-profiler`），独立于构建及其他性能测试运行。完整帧以输入/动画更新开始至 CPU 与 GPU 均完成计时，连续完成间隔判断吞吐和稳定性，不能用 CPU/GPU 分项或 P95 掩盖长帧。包含首次操作与首帧；主动空闲不算掉帧，不挑选最好一轮。先用空场景校准取显示缓冲的限速；同一客户端场景与 Metal 渲染器的离屏目标测原生绘制能力，窗口呈现结果另记，不能相互冒充。阈值与固定负载只维护在 `GATES`。

分析启动失败时可加 `--trace-startup`，按同一单调时钟关联 GUI、helper 和 Station 的阶段；结合系统日志区分进入程序前的系统评估与业务初始化。探针包含额外 IO，诊断后用同一产物关闭探针复测，保留各自报告。

启动门禁从 GUI 进入 `main` 计时，直到真实窗口交互生效、本机 Station 和内嵌 Agent 可用。进入 `main` 前的系统评估单独记录，不计入门禁。首次初始化及无预运行服务的再次启动均须达标；历史与远端连接按已批准口径随后恢复。使用隔离数据和真实运行时，不使用假 Agent、强制离线或人工驱动帧来缩短启动。测试的诊断等待上限不改变已批准门槛。

报告与日志留在忽略的本地产物目录；结束后确认只回收本次进程和 fixture。技能只维护批准规则与执行入口，不记录历次通过状态。交付前按 [skill 维护](../zork-skill-maintenance/SKILL.md) 核对一致性。
