# Chat 消息与交互

按任务读取 [Chat](../../../docs/design/chat.md)、[导航](../../../docs/design/chat.md#navigation) 或 [用户参与](../../../docs/design/user-participation.md)。以下守护身份、消息源和原调用接续；能力是否实现查当前源码。

## 身份与缓存

- Chat 身份独立，目标、验收和修改通过消息表达，不增加完成/取消状态。阅读、订阅、创建定义或打开 home 不隐式派工。
- Session 正文与主动 Chat 投递分开；按 [结束确认与后台接续](../../../docs/design/chat.md#configuration) 检查文本收尾、显式 `end`、发送回执及失败状态，不自动转发内部正文或因提醒重发消息。
- 作者、订阅者、创建者和执行者分开，由 core 按可信事实投影；未知不猜。首次发送才创建 Chat 并独立分配 Session；模型、思考深度和可选 Profile 绑定该 Session。协作创建新的 Chat，不依赖领队、队员或它们的授权。创建操作恢复沿用原身份；历史执行按真实绑定定位。
- 沿客户端、Agent 工具与 Mesh 的完整发送链路，按 [Chat 发送约定](../../../docs/design/chat.md#身份与消息) 核对本地消息状态、手动重发的身份、回推确认及传输重试；不能把业务工具的幂等恢复规则套到普通消息发送。
- 按 [消息源与恢复](../../../docs/design/chat.md#消息源与恢复) 核对每 Chat 的日志、持久化发布顺序及 epoch；索引可重建不代表业务库或附件可删除。源消息 append-only，core 可更新原卡片的派生缓存，保留 ID、位置与参数；归并在入库链路完成，不依赖窗口或卡片可见，不写回源日志。
- 结果先到先持久保存，请求到达合并后展示；重复、旧页或迟到尝试不能回退新结果。请求、归并、暂存清理及追赶水位一致提交，游标始终按原消息流推进。
- 普通 Markdown 网页链接由 core 从实际消息提取并增量入库，不要求额外页面投递工具；客户端连接身份作为消息事实沿源日志保留。
- 缓存重建和分页不重放副作用。动作采用版本化载荷，未知版本只读；普通正文和任意 HTTP 描述不是动作，不靠逐卡片轮询补齐状态。
- [本机脚本卡片](../../../docs/design/chat.md#本机脚本卡片)由用户在兼容客户端显式启动，core 管理执行与平台能力边界。发卡按普通消息完成，日志和原生回调只留本机，不登记待响应请求、回传 Agent 或接续原调用。

## 用户响应与原工具

- 按 [用户参与职责](../../../docs/design/user-participation.md#职责) 区分业务与注册管理；卡片、卡片请求、输入和结果属于业务。沿登记接口的参数、依赖及调用链检查，不能把含业务载荷的实现改名为 registry 就算分离。
- 原业务工具拥有参数、预填、校验和执行，保持 pending；已有业务请求由 Chat 发布引用；直接发送 OAuth 卡片时，chat.post_message 原调用拥有等待，登录业务仍拥有凭据和回调。不另建交互创建/等待工具。历史 Agent 配置请求沿原业务保持 pending 并注册卡片，用户确认或编辑后才执行；新的 Chat 创建直接使用首次发送的参数，不复用旧 Agent 创建确认流程。完整且不需要用户参与的修改直接执行；局部修改保留未编辑字段。
- 按 [面向用户的卡片](../../../docs/design/user-participation.md#面向用户的卡片) 审查内容与动作，不能用原始参数 schema 代替用户可理解的业务选择；展开、收起只影响呈现。
- 按业务归属与注册引用核对卡片、动作和结果，先结果后请求的暂存不能丢掉归属。业务在 core 管理客户端操作及恢复，在权威端验证操作者、权限和版本；原回执未明时不换 ID 重做。并发提交策略按对应业务判断，不能从业务探针推导为注册管理职责。
- 注册与通知先持久提交；需要 Agent 选择发布位置时，`user_action_required` 进入原 Session mailbox；已指定 Chat 的 OAuth 发送直接绑定发布，不再通知 Agent 重复发送。覆盖响应早于 waiter、完成早于发布及多 Chat 绑定同一请求；ID 本身不授予权限。
- 工具响应与公开消息独立投递。退订不切断原工具等待，工具通知不回灌频道；等待不持资源锁/事务，不增加全局工具名额或套用连接建立期限。
- 取消传到原调用和 owner，不等待原操作去重锁，提交时重验取消。Future 不跨进程存活：未接受等待明确失败，已接受但效果不明保留 unknown，不自动重放旧协议。

业务负责效果、回执和卡片结果可靠提交，外部效果沿原回执/outbox 恢复。登录以凭据实际保存为完成；其私有接口和输入属于登录业务，秘密不进入 Chat、Agent 通知或平台恢复状态。

## 验证

客户端职责按 [边界](../zork-client-boundary/SKILL.md)，水位和投递按 [同步](../zork-sync/SKILL.md) / [订阅](../zork-client-subscriptions/SKILL.md)。按 [验证规则](../zork-validation/SKILL.md) 覆盖先结果后请求、重启、重复/迟到、多端确认、绑定竞态和取消。接续必须观察同一 invocation 的实际业务效果，通用等待测试不能替代。

首次发送覆盖空草稿、明确拒绝、结果未确认、重复提交、重启和源消息先于回执；创建请求与本地首条消息一致提交，普通消息发送器不能接管创建请求，源回推只确认同一记录。

普通消息 wire 增加字段时覆盖新客户端到旧 Station 的滚动升级；明确拒绝必须保留原正文并投影可理解的失败原因，不能只用同版本 fixture 证明发送兼容。
